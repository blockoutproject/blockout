# Integration test boundaries

This reference describes the existing V2 test evidence and its canonical setups. It is test maintenance documentation, not a feature specification or acceptance record. Product requirements and pending native/provider qualifications remain in their owning `specs/` artifacts. The [scenario inventory](integration-tests.md) identifies the real components, controlled boundaries and detectable regression for the documented integration scenarios.

Use the installed [Java testing policy](../.agents/skills/java-testing/SKILL.md), its [canonical examples](../.agents/skills/java-testing/references/examples.md), the [Expo testing policy](../.agents/skills/expo-testing/SKILL.md) and its [examples](../.agents/skills/expo-testing/references/examples.md). Keep scenario inputs, the action and assertions visible with Given/When/Then phases. Parameterized rows are distinct boundary cases of the named scenario.

## Discovery and placement

Java tests mirror the production package below `apps/<owner>/src/test/java`. Put a transaction/use-case test beside the application owner, a persistence test beside the infrastructure adapter, and a binding test beside the API. Feature fixtures stay with that feature; `backend/testsupport/PostgresTestDatabase` owns reusable container/role/migration mechanics. Do not add a cross-module test framework.

The root [Maven configuration](../pom.xml) explicitly assigns `*IntegrationTest` and `*JpaTest` to Failsafe's `integration-test`/`verify` phases and excludes them from Surefire. Surefire's `*Test` pattern covers plain `*Test`, `*WebMvcTest`, `*JsonTest` and `*SmokeTest`. A JSON slice's name describes framework integration without implying HTTP. Configuration-runner tests retain `*IntegrationTest` because real Boot binding, validation or conditional wiring is the boundary. A directly constructed policy with mocked ports remains `*Test`.

Mobile tests retain the repository's co-located `__tests__/*.test.ts(x)` names and Jest Expo discovery. Their titles and the inventory distinguish schema-only, generated transport, Query/session and component evidence. A filename containing `native` describes the adapter being driven; Jest does not execute native SDKs.

## React component, form and screen patterns

The same family uses the same visible scenario shape: `// Given` declares the decisive inputs and required owners, `// When` performs the user action or native event, and `// Then` checks the resulting behavior. Keep blank lines between phases. A necessary lifecycle scenario can repeat When/Then pairs; do not hide another action inside assertions or combine unrelated cases. Parameterized rows state the differing boundary value. Names describe what this boundary proves, including controlled I/O and evidence limits.

The installed RNTL 14 APIs are asynchronous: await `render`, `renderRouter`, `renderHook`, `rerender`, `unmount`, supported `userEvent` operations and `fireEvent`. Use a scenario-local `const user = userEvent.setup()` for supported gestures. The installed canonical skill examples supply the behavioral pattern; apply the actual installed API signatures. Do not add a wrapper around RNTL.

### Providers, fixtures and helpers

Render composition stays local to the feature and lists its required providers. A reusable wrapper may supply an identical active provider boundary, but must not create unrelated providers, install mocks, seed the cache, perform actions, wait for hidden readiness or return a user-event session. Keep initialization doubles and scenario-specific responses visible in setup. `AccountFeedbackProvider` owns the shared session-generation feedback fixture; do not duplicate it under another local name. The collection HTTP peer owns response data, while each suite explicitly owns its QueryClient.

Simple values stay inline. Rich reused data uses a typed factory at the narrowest owner, such as [accountResponse](../apps/mobile/src/features/accounts/test-support/account-response.ts), [consultation data](../apps/mobile/src/features/sporting/test-support/consultation-data.ts) or the existing Pro offering/customer fixtures. Override the scenario-determining identity, capability, revision or amount explicitly. Do not construct expected results with the production mapper being tested, share mutable fixture state across tests or generate random edge cases. These deterministic scenarios need no new fixture dependency.

The narrow [nativeAlertAction](../apps/mobile/src/shared/native/test-support/native-alert.ts) helper selects an already displayed SDK action and fails if it is absent. The test still invokes it explicitly inside `act`; retaining that callback before changing session/resource proves stale-confirmation behavior. Render and interaction helpers must not accept a confirmation, submit a form, install a response, or recreate the application guard under proof. Explicitly named native-I/O fixture preparation may reset those doubles to documented defaults; scenario-specific responses stay beside the scenario. Avoid `pressAction`, `editField`, universal renderers, test-ID registries and custom test DSLs.

### Waiting, selectors and cleanup

Use `getBy*` for an established synchronous state, `findBy*` for a state that appears later, and `waitFor` for a specific assertion outside a single element lookup. The waiting callback contains assertions, never user actions. Model races with `Promise.withResolvers` at the I/O boundary: observe request admission, change the competing state, then resolve/reject the held response. No sleep or arbitrary timer advance establishes completion. Fake time belongs only to a clock-dependent contract such as expiry, delayed feedback or local date presentation, and must be restored.

Prefer role with accessible name/state, then label/display value/text/hint. Assert public RNTL matchers rather than `.props`, style objects, snapshots or tree serialization. The decorative sporting cover retains a testID because it deliberately has no accessible role. A small image `source` assertion may protect the exact URI sent to the native renderer when the scenario is stale-preview replacement; it proves URI forwarding, not actual image decoding. The disabled RefreshControl's missing public native `onRefresh` input is a scoped exception: RNTL `fireEvent` can bubble past the host and call the parent component's prop, so it cannot certify a disabled physical pull gesture. Native runtime evidence remains required for that gesture.

Unmount with awaited `cleanup()` before clearing clients, restoring spies/environment or disabling fake time, so owners dispose subscriptions while their dependencies still exist. Explicitly registered observers/subscriptions use `finally` or teardown even on assertion failure. Restore focus/online managers when changed. Each test receives a fresh client and controlled mocks; a file-level environment snapshot is restored after each test (delete keys that were originally absent). Automatic RNTL cleanup suffices only when no dependent resources require ordered teardown.

### Review and regression evidence

Review every changed test and helper against the Expo policy and canonical examples, including untouched elements of the changed file. Check whether the assertion would fail if the relevant production guard, submitted value, decode step or cleanup were wrong. A passing suite alone does not answer that question. For important paths, temporarily perturb one production behavior, run the named scenario, inspect the relevant failed assertion, restore the original bytes in `finally`, and rerun green. Keep mutation scripts and transient logs outside the repository; the delivery PR records the exact mutations and results.

Jest component evidence establishes JavaScript behavior with the stated doubles. Native evidence requires an installed development build on the specified device: keyboard, gestures, OS focus, native files and SDK presentation are not certified by Jest. Provider evidence requires the actual configured provider and authorized inputs. The opt-in [maintenance provider suite](../apps/mobile/src/features/access/__tests__/maintenance-settings-provider.test.tsx) makes real backend requests when configured; its skipped cases are unavailable evidence, not passing component tests. This test-only normalization does not renew any native, visual or external-provider approval. Coverage percentages do not replace these distinctions.

## Choosing a smaller boundary

Spring-backed PostgreSQL suites import the native [PostgresTestConfiguration](../apps/backend/src/test/java/com/blockout/backend/testsupport/PostgresTestConfiguration.java) and close their context after the class. A container must remain available until its datasource and application consumers are destroyed; JUnit-owned containers combined with cached Spring contexts violate that order. The direct startup/role runner retains `@Container` because it explicitly closes each application context while the container is still running. No service-connection override may replace the restricted application role with container-admin credentials.

Choose the smallest setup that can fail for the named regression. Mocking an application persistence port is appropriate for orchestration; it cannot prove SQL uniqueness, commit, rollback or locking. A simulated health indicator proves Actuator's status/security mapping; the separate real PostgreSQL health suite proves database failure behavior. A generated binding adapter proves the contract boundary even when business implementation is still pending, provided the assertion checks values actually bound by MVC.

Split mixed suites when the same class would otherwise advertise HTTP while most cases only call a serializer, or advertise native scheduling while the scheduler itself is mocked. Preserve the assertion and move it to the correctly named family. Do not add production abstractions, test-only mappings or eager loading to accommodate a fixture.

## Verification and limits

Use the actual [README commands](../README.md#verification) and [CI workflow](../.github/workflows/ci.yml). Run `clean` when classes move or change suffix so stale compiled tests cannot inflate evidence. Inspect fork shutdown diagnostics as well as assertion results: a forced JVM exit after a shutdown timeout is an unresolved lifecycle defect even when Maven reports success. Regenerate consumers before verifying affected contract boundaries. Run the whole owning module after targeted tests and the root verification for shared setup/build changes. Exact executed commands, counts, failures and unavailable qualifications belong in the delivery PR.

The collector-to-backend suites require the existing [opt-in qualification setup](../README.md#collector-to-sporting-qualification). Ordinary `verify` intentionally skips them unless enabled; a skipped test is not passing evidence. Real-provider, retained-data, native-device and production operations require their own authorization and evidence. No normalization result completes pending feature tasks.
