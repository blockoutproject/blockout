## Coordination and lifecycle

`AccountErasureCoordinator` composes only actual owner APIs. Acceptance and owned SQL erasure/minimization share a coherent local transaction; each module owns its statements. Capture external target references before removing the only usable correspondence. External Auth0/RevenueCat/S3 calls occur after commit. No transaction is held over a provider request, and no SQL rollback claims to compensate a provider success.

All delayed local results carry the original immutable account UUID and are checked against current status. Mobile generation clearing remains F13. After a completed erasure, a new account gets a new UUID and default capabilities only. Same Auth0 subject plus still-valid old token may resolve to that new UUID under the explicit standard-token decision; this does not authorize stale tasks to switch target UUIDs or transfer old personal data.

F09/F07's later plans implement their own received interfaces and qualification. F05 tasks declare these dependencies rather than delivering partial fake cleanup or creating their schemas. A feature may be individually tested with controlled adapters, but end-to-end deletion cannot be called qualified until the real domain participants exist.

## Model/contract ownership

F05's public profile has only current UUID, neutral/customized username, provider contact email, photo presence, profile revision and nullable reliable principal creation instant. No tokens, raw Auth0 payload, payment customer record, permission-edit interface or provider alias list is exposed. Other features consume narrow domain APIs rather than this mobile DTO.

OpenAPI schemas are documentary snapshots; F13 owns the single future `contracts/shared/schemas/problem.yaml` definition. F05's local problem projection carries that profile without extending it with account IDs. Generation tests prove Java and TypeScript real consumers; F13's cross-language synthetic qualification also checks Python without inventing an F05 Python runtime consumer.

RevenueCat SDK state is the sole Pro entitlement decision consumed by mobile. The backend has no projection API, periodic rights refresh, extra grant ledger or server-calculated offline tolerance. Unknown/no SDK state means no ad or purchase invitation; SDK-inactive state follows F11 consent. F07 cleanup removes personal inbox and installation associations; match-level processed-announcement facts carry no account identity.
