## Projection and privacy

Commit a name, alias, classification, club attachment or effective city change. Expected: the after-commit task reads current data and updates all dependent resources. Roll back the business write: no projection effect. Run the non-web operator entry point: it starts no second index scheduler, and its relevant changes appear through the serving backend’s next full rebuild. Change only a score: no unnecessary search rewrite. Restrict a city while the index still contains it: no old-city match or old contact reaches the response; a candidate may be temporarily omitted until reindexing.

Fail a targeted update or stop the process before queued work runs. Restart and exercise the fixed-delay rebuild: lost work catches up without a durable retry record. Mutate data during a rebuild; queued tasks execute afterward using current values. Fail one bulk item, a whole request or the final refresh: old usable aliases remain. Lose the alias-update response: reread native alias state before cleanup, and never delete an active generation. Fail cleanup: diagnostic only, no destruction of unrelated indexes.

Restore authoritative PostgreSQL into isolation and rebuild the derived search state before use. Verify prior valid results survive an interrupted replacement, current restrictions still apply, and failure/last-success diagnostics contain no query text, credentials, contacts or raw payload. A scheduled run or successful HTTP bulk envelope alone is not proof of an indexed generation.

Qualified lifecycle boundary: `SearchProjectionIntegrationTest` runs migrated PostgreSQL 18.6, actual F02 current reads/after-commit events, the one-thread Spring scheduler and real TLS OpenSearch 3.9.0/client 3.10.0 under Microsoft OpenJDK 25.0.4. Ten cases establish commit versus rollback, current rereads behind a full run, club/division/participation dependents, removal of hidden teams, full-run catch-up without an event, refreshed native document serialization, failed bulk-item/refresh preservation, lost alias acknowledgements and an alias request applied after the old-state reread. Native failures and delayed acknowledgements use controlled SDK call boundaries against real owned indexes; they are not a process-kill or hosted failure injection. Bulk calls assert that SQL transactions have ended and that execution stays on the sole search thread. Cleanup preserves aliased/unrelated indexes and removes at most twelve unaliased UUID generations; failed/unconfirmed runs defer cleanup until a later confirmed full run. The existing F02 `SportingProjectionIntegrationTest` also qualifies source/season scope expansion, score-only exclusion and transaction handoff under its real owners.

`ProjectSearchTest` covers bounded multi-page reconstruction and current identity/removal orchestration. `SearchProjectionSchedulerTest` exercises projection submissions and immediate fixed-delay registration; `SearchProjectionConfigurationIntegrationTest` qualifies native delay validation, the disabled non-web context and separation from the ordinary Spring scheduler. `SearchDiagnosticsIntegrationTest` exercises the actual Boot ECS encoder and native metric registry: rejected submission, failed bulk envelope/items, failed metadata cleanup and truthful latest-full-success state exclude synthetic query/city/contact/credential/raw error content.
