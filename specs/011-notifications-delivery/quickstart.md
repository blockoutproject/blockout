## Qualification boundaries

Apply [F13's proportionate qualification](../003-shared-quality/plan.md#proportionate-qualification). Deterministic Query/Router and server tests own delayed responses, cancellation, first refusal before retries, original-account callbacks, member disappearance, retained reappearance and server elapsed-age boundaries and ordinary-event local filtering. A loaded entry may cross 29 days on an unchanged page without a timer, request or immediate visual change; its next ordinary inbox read, opening or foreground event filters it, including offline. Test that distinction with the existing controlled clock, without a timing framework. Paris/New York and daylight-saving permutations belong to automated time-policy tests.

Use compatible native iOS/Android development clients for representative inbox loading, return, unavailable-target, link-absence and safe Retry journeys. Authorized pages/cursor survive in Query during an outage. Initial/full-reread final failure uses the scoped Error card and same-card Retry under [F13 FR-031/FR-036–FR-038](../003-shared-quality/spec.md#functional-requirements). Next-page-only failure keeps authorized entries, controls and the native scroller/position mounted with the shared compact error/footer Retry. Apply this when accepted pages remain even if expiry filtering renders no entries. Repeated edges start no read; footer Retry fetches only the failed cursor, retains the list through repeated failure and appends success without duplicates or read-marking replay; paused/background operations never create explicit-action progress. Known-refused rows leave immediately and cannot return after a failed reread. Verify one ordinary actual account departure/switch with private rows, reusing applicable F05/Query evidence for the same integration. Do not reproduce precisely timed response/account races manually. Check the native time adapter briefly by changing the device time zone and confirming the same sporting instant in local presentation; do not repeat every expiry/DST case on devices.

Distribute light/dark/system appearance, narrow layout, enlarged text and read/unread distinctions across representative shared compositions rather than every family × state × appearance × device. All editorial variants and missing/corrected facts remain covered automatically. Actual push permission, native token/storage/global-effect ordering, foreground/background behavior and receipt retain T041's physical SDK/provider evidence below. Observe clearing a previous app-controlled badge separately within platform capabilities; it does not prove push receipt or control of launcher-owned indicators. Functional simulator/emulator checks establish none of those provider outcomes. Reuse evidence only at its demonstrated boundary and keep unexecuted T041/T046/T060 obligations pending.
