# Tasks: F14 V1-to-V2 continuity and transition

**Input**: [spec.md](spec.md), [plan.md](plan.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/README.md](contracts/README.md) and [quickstart.md](quickstart.md).

**Prerequisites**: Accepted owning sources, [constitution](../../.specify/memory/constitution.md) and [agent guidance](../../AGENTS.md). This is an implementation and future transition work list, not authorization to inspect independent repositories, export personal data, change providers/prices, reset data, publish or retire production. Each external/destructive operation below requires its own authorization and actual prerequisites.

**Tests**: A01–A36 and SC-001–006 require the controlled and actual qualification below. Write meaningful failing automated tests before associated code. Prepare manual scenarios before executing them; distinguish synthetic fixtures, installed V1 binaries, actual signed upgrades, provider outcomes and population reconciliation. Documentation, source observations or a few successful accounts do not prove a transition.

**Organization**: Shared setup and early installation initialization, then five P1 stories in specification order and final qualification. Early initialization and legacy compatibility implementation do not wait for final cutover. F05/F09/F01/F02/F04/F07/F11/F12/F13 keep their existing implementation owners.

## Format: `[ID] [P?] [Story] Description`

- `[P]` denotes separate files with no unfinished dependency between those tasks, after stated prerequisites.
- `[USn]` follows the owning specification; setup/foundation/polish have no story label.
- All tasks remain unchecked until their actual implementation or qualification succeeds. Missing operational evidence blocks the affected operation, not unrelated implementation.

## Path Conventions

- Installation/discovery: `apps/mobile/src/features/onboarding/` with co-located tests, thin Expo Router entries and composition in `apps/mobile/src/app/_layout.tsx`. F05 owns the Auth0/session provider.
- Legacy status adapter: `apps/backend/src/main/java/com/blockout/backend/legacy/` with mirrored tests under `src/test/java/`; canonical `contracts/http/legacy-mobile/openapi.yaml` generates only the provider interface/DTO.
- Continuity/release instructions extend `infra/operations/README.md` and relevant existing deployment/build configuration. Public qualification outcomes live in the native `quickstart.md`; private associations, photos, credentials and provider evidence stay in explicitly authorized private locations.
- No migration application, database ledger, alias engine, second support/identity store, synchronized logo exporter or release orchestrator is introduced.
