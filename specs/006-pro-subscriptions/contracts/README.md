## SDK source and consumer coordination

The [published UI source](https://github.com/RevenueCat/react-native-purchases/blob/10.13.0/react-native-purchases-ui/src/index.tsx) and upstream package types are authoritative for callback signatures; do not copy editable SDK DTOs into this folder. Generated HTTP DTOs remain governed by F13, independently of this native boundary.

Account, advertising and navigation consumers must agree on unavailable versus inactive state and current-session attribution before integration. F05 publishes session changes without waiting for RevenueCat; F09 clears old presentation immediately and orders its native identity calls under the [SDK lifecycle](../plan.md#identity-and-sdk-lifecycle). Until current association succeeds, Pro is unavailable and F11 suppresses ads for the signed-in account. SDK events trigger current native reads rather than directly attributing their payload to the active session. Neither optional fields nor newly observed native outcomes may be silently interpreted as inactive, paid or cancelled. Preserve truthful native facts and private assistance for unsupported results; do not create an app Verify state.

The existing Pro owner hosts one standard React Native Modal containing only official `RevenueCatUI.Paywall`, supplied the real explicitly resolved shared `default` offering. Existing connected entries open it for free, paid, gifted and unknown-rights accounts after successful current association. Missing/failed opening gives brief originating-screen feedback. Dismissal returns to that source; logout, accepted erasure and account replacement remove the host. No commercial route/catalogue Query, `presentPaywallIfNeeded`, direct `CustomerCenterView` or application `restorePurchases()` fallback remains.

Native Paywall purchase/restore callbacks feed the existing current owner; a callback never starts a second restore or confirmation read. The SDK retains concurrency and rights observation after view disposal without a global busy reservation. Use supported configured restoration, original-store management and assistance within the standard native journey. A generic Buy control for an active account or absent Paywall Custom Action callback remains an accepted native limitation. Installed public API/configuration limits and actual subscriber propositions are qualified under the [plan](../plan.md#entry-offers-and-assistance); no unsupported callback, purchase interception, hidden/disabled provider control, URL-routing workaround or Blockout substitute is introduced. The independent Profile support action remains F10-owned and usable after provider failure.

V1 and V2 use the same existing `default` offering and published `Blockout Pro` Paywall, project, products, entitlement and platform keys. `REVENUECAT_OFFERING_ID` explicitly selects `default`; never fall back to implicit current. Adapt that shared paywall within authorized configuration scope and qualify V1 compatibility. Native store prices remain unchanged until separately authorized V2 cutover; F14 owns the 2.99 EUR reference to 1.99 EUR decrease, cohorts and publication. No server API version or mobile minimum-version change is needed for this configuration choice.
