## Contract boundary

With the canonical roots and selected generator configuration present, lint and bundle each root using Redocly; generate backend interfaces/DTOs, collector RestClient and mobile Query/Zod output at the same revision. CI runs the owning Maven compile/tests and mobile typecheck/Jest targets from a clean checkout.

When introducing or changing a generator or its configuration, also regenerate from clean output directories, compare normalized results and verify that generated outputs remain ignored. This targeted qualification avoids a second generation on every CI run. Expected: reproducible output, no generated source committed, no template patch and all actual consumers compile.

Exercise actual HTTP entry/decoding paths, not only schemas in isolation. Backend request tests cover required/optional/nullable/empty values, nested unknown properties, wrong types, enums/dates, safe Problem Details and refused effects. Mobile tests cover generated-schema validation once before Query success/cache, malformed/partial JSON, additive responses, 204/non-JSON, cancellation and bounded timeout. For cancellation, exercise Expo Fetch’s native rejection and the adapter’s error translation; do not require an application workaround for a Fetch implementation that ignores its AbortSignal.

For the collector, exercise valid nullable/additive responses through the configured generated client, native decoding failures, partial sporting outcomes, bounded waits and uncertain-write failure without replay. Verify actual backend serialization of required fields, including runtime null, target pagination and outcome counts. The [accepted decoding limits](contracts/README.md#source-composition-and-generated-outputs) do not promise exhaustive rejection of invalid backend data; do not test that upstream gaps must persist or introduce compensating validation. Inspect the clean collector package for the selected generated RestClient/Jackson-only runtime; no response-validator dependency or bundled runtime contract is required. Generator requirements and mobile schema admission still need their own qualified paths; no unchecked mobile cast is authorized.
