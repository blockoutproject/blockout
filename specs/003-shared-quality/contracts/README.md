No production routes/contracts are currently implemented, and no prior contract source exists to reuse in this rebuild. The root paths are decisions for later authored sources; this delivery creates neither empty OpenAPI roots nor placeholder business operations. Owners' plans must add actual routes/DTOs to these roots, not make per-feature copies. F13 establishes transport/generation policy and health semantics without inventing F01 batches, pagination, account objects or every future endpoint.

Health exposes at most a minimal readiness result, uses a bounded database connectivity/readiness check and never returns stack traces, SQL, credentials or admin diagnostics. Planned maintenance does not make a broken database healthy. Suppressing expected maintenance alerts must not convert absent telemetry into success. Private framework diagnostic endpoints remain unexposed by default.

## Source, composition and generated outputs

1. Author YAML using OpenAPI **3.0.4**, explicit schemas and `$ref`. Root security requirements are environment-appropriate; exceptional public operations explicitly declare their access. Use unique operation IDs within the generated consumer namespace and owner-meaningful schema names; resolve collisions at the semantic owner before generation.
2. Redocly CLI **2.62.1** validates each root, then bundles its references. Shared primitives are referenced, not copied. There is no extra join/assembly/export stage.
3. OpenAPI Generator **7.26.0** emits Spring interfaces and transport models for the backend, with supported Boot 4/Jackson 3/Bean Validation configuration. Emit the collector client with `library=restclient`, Boot 4/Jackson 3. Compile through the owning Maven builds/BOM instead of accepting an unrelated generated project scaffold.
4. Orval **8.41.0** emits TanStack Query functions/hooks, transport types and Zod schemas from the same mobile bundle. Select React Query + Fetch, Zod schemas, runtime validation and `includeZodSchemaInArguments` for the custom mutator. The mutator owns the one validation call; turning on runtime validation alone does not validate custom transport responses.
5. Generate into ignored build directories and compile/test every affected actual consumer at the same source revision. Generated outputs, bundles and caches do not enter Git. No patched templates, manual generated edits or JPA-to-contract export.

The Java `disallowAdditionalPropertiesIfNotPresent=false` option lets explicit OAS policies govern instead of the generator's legacy restrictive default. Collector unknown-response-property tolerance does not waive required-field/type/enum constraints. Generated annotations/types prove neither invocation nor runtime validation.

For normal business JSON responses, use generated named object/array schemas whose validation path is qualified. Orval's inspected path skips primitive, void and NDJSON schema passing: 204/non-JSON are handled intentionally; any later required primitive/stream shape needs a supported qualified schema path before adoption. An unexpectedly absent success schema is a failing boundary qualification, never a cast. Do not invent wrapper objects solely to conceal unsupported domain semantics.

## Shared HTTP behavior

- Authenticate backend JWTs with expected issuer, environment audience, expiry, allowed client and necessary scopes. M2M has its own client/audience, never mobile credentials. Business authorization remains in the owning use case; a valid token alone is insufficient.
- The focused mobile transport preserves cancellation signals, bounds waiting and classifies safe network/HTTP/schema errors. It validates successful business JSON exactly once before Query success/cache. Parse non-success responses through their error profile, not the success schema. No raw sensitive response is logged on validation failure.
- RFC 9457 Problem Details uses `application/problem+json`, stable machine `type`, category `title`/`status` and safe details. Optional instance/owner extensions must not leak private references. Known types map to accepted presentations; unknown types map to the existing generic error. Do not duplicate `type` with a separate generic code catalogue.
- Each operation documents meaning, authorization, effects, units, bounds, examples, errors and uncertain-result behavior. Property names are camelCase. Owners select dates/time-zone meaning; formats must be validated in actual consumers rather than presumed from OpenAPI annotations.
- Define requiredness separately from nullability (`nullable` in this dialect); empty is a third value. Reject unknown request properties, including nested objects, except intentional typed maps. Responses allow additional fields but require valid known fields. Do not silently strip an invalid request and accept it.
- Bound requests and waits for the actual owning operation, without a speculative global throughput programme. A cancelled/timeout mutation may already have committed. No ordinary automatic mobile retry or network-reconnect replay; token renewal grants no permission to replay an uncertain write. Owners choose safe reread/duplicate handling, including F10's accepted manual exceptional case.

## Compatibility and coordinated changes

Mobile and ingestion roots describe surfaces of one backend deployment. Several plans may change either root. Each change names the semantic owner, provider and real consumers, reuses existing operations when their meaning matches, and regenerates/compiles/tests those consumers together. Resolve a conflicting shared definition before either dependent plan relies on it. Cross-repository consumers, if later authorized, need an exact read-only revision rather than another editable authority.

Required fields, enum additions, changed null semantics, error meaning and authorization can break existing consumers even when a schema diff appears additive. All F12-admitted mobile versions remain supported. Plan a compatible provider transition through actual new-binary availability in both stores before any explicit minimum-version change; no immediate forced update is inferred from backend release. Keep OpenAPI dialect, product version and API compatibility separate. No URL versioning scheme is invented solely because two surfaces exist.
