# F13 cross-feature inputs

## Authority

This matrix derives the common foundation from the accepted specifications, the
[constitution](../../.specify/memory/constitution.md), the
[approved architecture](../../docs/architecture.md), the
[owning specifications](cross-feature-inputs.md#owner-matrix) and the
[F14 transition requirements](../014-v1-v2-transition/spec.md).
F-numbers are functional owners, not directory numbers. F13 supplies shared
mechanics and evidence; it does not implement or redefine every dependent feature.
The detailed decisions are in [research](research.md) and [plan](plan.md).

## Common timers and retention remain distinct

| Rule                                                                  | Owner and interpretation                                                                                                                                                                                                |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mobile read: 10 seconds per attempt; one extra attempt after 1 second | F13 technical bound for transient, safe reads only. No retry of cancellation, invalid response, authentication/permission/business refusal. Navigation remains escapable.                                               |
| Mobile mutation: 30 seconds; upload: 60 seconds                       | F13 technical waits, no automatic replay. Deadline expiry is uncertainty when acceptance may have occurred; the domain determines reread/reconciliation.                                                                |
| Provider acquisition: at most two extra transient read attempts       | Approved architecture constrained by F01 provider limits, `Retry-After` and cycle semantics; parser failure is not retried as a transport failure.                                                                      |
| Pro: standard SDK cache/expiry                                        | F09 owns consumption; no independent five-minute/72-hour guarantee.                                                                                                                                                     |
| Access configuration: complete cold-start check and explicit retry    | F12; no persisted snapshot, age allowance, foreground check or timer. Current-process restrictions and revisions remain protected.                                                                                      |
| Push: best effort                                                     | F07/F12 inbox survives push failure; no persistent retry window or maintenance catch-up.                                                                                                                                |
| Notifications: daily age-29-day purge / age-30-day exclusion          | F07, elapsed 24-hour days, distinct from backup and diagnostic retention.                                                                                                                                               |
| PostgreSQL backups: every 30 minutes, expire after 30 days            | F13; scheduled interval is not a guaranteed loss bound. Expiry still runs if no new successful backup exists.                                                                                                           |
| Images: AWS Backup hourly periodic, 30-day retention                  | F13 selected standard protection; preserve source objects/URLs and restore bytes/associations.                                                                                                                          |
| Diagnostics: Grafana 14 days, Sentry 30 days                          | F13 selected destinations; effective native Free retention must be qualified. IRM retains its native incident history; no duplicate Blockout incident archive. No duration transfers to assistance or business records. |

## Evidence boundaries

Qualification must exercise actual server refusals, generated consumers, native
journeys, retention and isolated restoration. Approved prototype/Figma evidence
supports unchanged presentation, not SDK, provider, purge or backup execution.
Required checks and unavailable evidence are recorded against the actual artefact;
no test or production result is claimed by this input matrix.
