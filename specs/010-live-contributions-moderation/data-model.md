# Data model: live contributions and moderation

## Persisted responsibilities

| Entity                   | Necessary data                                                                                                                                                                                | Integrity                                                                                                                          |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Match contribution state | Match UUID, editing revision, nullable reference to the version causing the unresolved report hold                                                                                            | One per match with contribution activity; absence reads as initial revision/no hold. Create while holding the existing match lock. |
| Contribution version     | UUID, match UUID, address, platform, nullable owner account, state, creation instant, quota-participation flag, optional source/replacement version, useful decision kind/time/nullable actor | Backend-only writer. Address/creation/quota participation are immutable. Decision changes state, not the submitted address.        |
| Report                   | UUID, version UUID, nullable reporter, nullable free-text reason, original time                                                                                                               | Original reason immutable except erasure; report remains counted after attribution removal.                                        |

These are business records, not a universal event log. Publication/approval and the later lifecycle decision explain the current version; replacement and source relations preserve its useful lineage. Approval and any later removal/replacement retain their relevant decision timestamps and nullable actors without a general command journal. Source/replacement references and the unresolved hold reference must belong to the same match. Hiding sets that reference; moderator selection clears it. It replaces a separate stored hold boolean and identifies the one unresolved hidden version without reconstructing an event journal. Do not expose report authors through moderation DTOs.

Use foreign keys with nullable attribution on account deletion; report reason clearing belongs to the same F05 erasure transaction, not just an ON DELETE association change. Partial unique constraints enforce one active version per match, one pending version per non-null owner/match, and one report per non-null reporter/version. Anonymous reports use distinct rows: never apply NULLS NOT DISTINCT or count only non-null reporter IDs. Pending ownerless versions may coexist after erasure and remain available to moderation.

## Transitions

| Operation                | Preconditions and resulting state                                                                                    | Associated effects                                                                                                                                             |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ordinary submit          | Usable account/current grants/time/ownership/quotas; active before definitive result outside hold, otherwise pending | Different own pending proposal becomes superseded; immediate publication replaces own active version. A refusal changes nothing.                               |
| Withdraw                 | Own active version with ordinary withdrawal capability, or authorized moderator → withdrawn                          | No quota refund and no automatic promotion of pending proposals.                                                                                               |
| Approve                  | Pending → active                                                                                                     | Preserve owner; replace active version, supersede all other pending proposals, clear report hold.                                                              |
| Reject                   | Pending → rejected                                                                                                   | Preserve active version and independent hold.                                                                                                                  |
| Direct moderator publish | New active version with moderator as owner                                                                           | Bypass window/quotas only; replace active, supersede pending proposals and clear hold.                                                                         |
| Reactivate               | Rejected/withdrawn/hidden/replaced/superseded historical version → new active version                                | Source remains historical; copy address/platform and still-present owner, no reports or quota participation; replace active, supersede pending and clear hold. |
| New report               | Another owner's currently public version, including ownerless; one per account/version                               | Count all retained reports; hide at threshold 3 before definitive result or 10 afterward and set match hold.                                                   |

Historical cancelled versions and their decision values remain readable and cannot be reactivated; no executable pending-cancel operation remains. A duplicate report retains the original reason and does not evaluate the threshold again. If already recorded it can return current own reporting state even after that version was hidden; it never reports a replacement. Sporting correction alone neither publishes a pending version nor re-evaluates report hiding. F02 visibility still governs exposure and publication.

The revision advances once for an accepted contribution mutation, including a new report, and remains unchanged for a no-op. Its wire representation is an opaque nonempty string. The server compares under the match lock, before changing state or recognizing an unchanged submission. No-op decisions only return existing state when the exact target is already in the requested terminal state; an incompatible state is a conflict. Reactivation always creates a version, so an obsolete repeated intent is refused. This revision does not replace current sporting/permission checks.

## Transaction and quota boundaries

Acquire the existing F02 roots in their prescribed order, including the match for all contribution writes, then concerned accounts in sorted UUID order. Retain actor/attribution account locks for their actual authorization, quota and erasure responsibilities. F07 selects an audience once only for a newly allocated announcement, without audience account locks or a second selection. Private, unchanged and nonallocating submissions do no audience work. Existing foreign keys/cascades preserve selected-account integrity; required publication/inbox effects remain atomic and an inbox insertion failure can roll back publication. Re-read grants, original actor identity and version ownership after locks. A reactivation that observed an owner before erasure must not copy stale attribution after obtaining that account lock. F05 erasure holds its account lock and changes nullable attribution/reasons without acquiring sporting roots. Avoid flushing contribution updates before the account-lock phase.

Within this transaction, derive ordinary usage from versions whose quota flag was fixed true at creation: at most three for the owner/match and at most three distinct match UUIDs for that owner between successive Paris midnights. A same-day match consumes no additional distinct-match slot; the per-match version limit still applies. Check an unchanged active/pending address before quota refusal, after revision and current authorization. State changes and later rights changes never refund/reclassify usage. Moderator-created versions and reactivations use false; approval keeps the original flag.

Update the old active/pending states before inserting the replacement where needed by partial uniqueness; use ordinary JPA flush ordering and qualify it on PostgreSQL. Do not remove uniqueness to accommodate ORM ordering. Any constraint failure rolls back the full command and its required internal F07 effects. Map recognized state conflicts safely; unexpected database faults remain failures rather than invented success.

## Read projections and lifecycle

Personal reads expose only the caller's versions, eligibility and ordinary usage. An optional `activeContribution` exposes the exact caller-owned ACTIVE version independently of paging and is absent for another owner or no active version. Their `proposalCount` counts all retained versions for that original account and match, including active and terminal states; zero is explicit. It is independent of the twenty-item page, ordinary quota participation and other accounts/matches. The page, total and context share the same short repeatable-read transaction. Moderation may read a hidden match but may not publish through its restrictions. Related counts/context/pages use a coherent short read transaction, with no cross-page snapshot guarantee. Version/report ordering is time descending then UUID ascending; match queue ordering uses the maximum creation, useful decision or report time, then match UUID. No stored activity counter or scheduling task. Match badges count the active version, pending proposals, the unresolved hidden version (zero or one), and reports on the active or unresolved hidden version. Rejected versions have a separate historical count. All counts come from SQL, independently of pagination; older reports remain available on their exact historical version.

Mobile drafts remain route-local RHF values, dirty state and a coherent viewed target/revision; they are not persisted entities. Required-read loading/error/Retry preserves that owner and its native ancestors, with admissible address/reason, choices and prepared files. Query alone retains admitted server pages and read state. Initial/full-read failures consume [F13’s form composition](../003-shared-quality/plan.md#frontend-form-conventions), hiding all editable form content and save controls while the same RHF visit, useful revision and native ancestors remain mounted; next-page-only errors retain the list/footer. Ordinary failed writes preserve editable input without imposing a prerequisite reread, under the [plan’s mutation policy](plan.md#mobile-state-and-failures). Current errors never restore forbidden private data, revoked actions or another account’s state. Own-contribution history and moderation pages retain their private refusal scopes; an old public sporting title or card is a separate projection that updates on its own ordinary read. Ordinary writes use direct actions, normal mutation feedback and invalidation; a later explicit authorized action needs no successful-read prerequisite, and a read Retry performs no write. An acknowledged command remains accepted after a failed dependent read.

Account deletion clears author/decision references and report reasons, preserves counted facts, holds and historical versions, and cannot restore ownership on re-registration. It does not create new moderation activity or refund another account's quotas. F11 governs any personal information inside addresses through its existing rights procedure. No raw provider content, new retention duration or irreversible historical account mapping is introduced.

F07 reads accepted link transitions under the same match transaction and owns announcement allowances. Version creation and zeroed reports do not imply a new announcement allowance. Sporting result composition reads the current permitted link under the shared lock; pushes occur only after commit.
