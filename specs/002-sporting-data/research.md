## Resolved design questions and remaining evidence gates

No product decision is left as `NEEDS CLARIFICATION`. An unavailable proof is not a license to guess: the chosen behavior for every unresolved correspondence is to preserve existing accepted state and diagnose the unattached observation.

| Evidence not established                                      | Selected behavior until qualified                                                       | Success needed before enabling dependent capability                                                                               |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Universal FFVB full-export coverage across reused pools/tours | Explicit source scope and actual covered rounds; no withdrawals outside covered scope   | Controlled complete/noncomplete cases plus same-season reference evidence; valid empty distinct from invalid code's identical CSV |
| LNV historical phase season metadata                          | Use only separately qualified source context, not match year                            | Official attributable season/competition/phase catalog evidence                                                                   |
| Golden-set score where only an indicator exists               | Separate `present` indicator and unknown score                                          | Explicit attributable golden-set score, never an invented sixth ordinary set                                                      |
| Actual generator/validator behavior                           | Documented source and future blocked consumer acceptance                                | Locked generation twice, actual Java/Python/TypeScript consumers, strict request/additive response cases                          |
| Native design/upload/session behavior                         | Reuse approved journeys; no native success claim                                        | Actual iOS/Android evidence for changed boundaries, current user/session permissions and valid byte transfer                      |
| V1 logo bytes/correspondences                                 | Retain unresolved protected manifest, do not fabricate clubs or successful preservation | Authorized F14 inventory and restored bytes with hashes, certain current mapping and unchanged newer V2 edits                     |

The measurements support choosing a bounded acquisition shape, not guaranteed speed or a cap on matches. No additional recovery service is justified. Provider APIs may evolve; requalify changed parsing/context evidence through the owning implementation work.
