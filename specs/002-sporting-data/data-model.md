# F02 derived data model

**Authority**: [F02 specification](spec.md) and consumed owners in [consumer contracts](contracts/consumers.md). This is a logical schema and application model, not an executed migration. `sport` owns its tables; acquisition cycle/configuration records remain F01-owned and are accessed through its application interface.

## Identity and relational constraints

Internal IDs are immutable UUIDs. Foreign keys retain identities; absence is not deletion. Use PostgreSQL constraints and owning application validation together. Do not expose JPA entities or generated DTOs as domain models.

Raw supplier team labels are bounded current identity evidence, not arbitrary diagnostics. Verified alias changes cannot silently change a club or merge existing teams.

Use foreign-key and uniqueness indexes plus actual reads by `(pool, season)`, qualified source reference and current dirty revision. Do not predefine a speculative indexing program or use JSON blobs to avoid relational identity constraints. Classification consistency across related rows is checked under the owning scoped transaction; ordinary SQL FK/uniqueness protects concurrent writers.

## Transport observations versus accepted values

Observation field states are `KNOWN`, `UNKNOWN`, `INVALID`, `CLEARED`. A known field has its typed value; the other states do not carry a value. Invalid includes a safe reason code, not raw input. Unknown does not erase usable accepted evidence. Cleared means the adapter established explicit removal under that field's policy; an empty or unparseable string alone does not establish it.

An accepted field retains source/context, backend cycle order, observation/acquisition/integration times, optional actual provider publication time, usable value or explicit-clear marker. No complete raw-response or contact history. Store only current eligible source slots necessary for precedence/current automatic values. F11 restriction/erasure removes disallowed content from all slots and overrides, including diagnostic material.

Professional match and standings facts come only from LNV pages. Other covered competitions use FFVB. Retain the designated source’s useful known/clear state during failures; unknowns are not filled from another professional source. No priority election, authority upgrade or secondary-only candidate state is needed. Manual presentation/privacy restrictions remain independent.

## Calendar state, order and finalization

`acquisition` issues a cycle identity, its mode (`PERIODIC`, `MANUAL`, `INITIAL_RECONSTRUCTION`), source/context and monotonic order. Python echoes these; Spring resolves and compares the stored issuance. Each source/context admits at most one payload for a given observation identity; same identity with changed content is a conflict. The retained digest describes the normalized payload for current/recent cycle diagnostics, not a raw archive or universal receipts store.

Maintain a scope's latest admitted order to prevent an older request from writing after a newer scope request, and per-match/field last accepted order so successful partial writes are not undone. Admission is a short transaction. Each match transaction rechecks the applicable order/current restrictions under the same scoped concurrency fence; no HTTP-long SQL transaction. A newer admitted cycle makes the old request's remaining work stale/incomplete. F01 completion/reset of an incomplete cycle does not erase sporting successes. Replay of the same payload/cycle may finish failed matches only while still eligible; after a newer cycle it is harmless stale work.

Track candidate match IDs accepted by this processing attempt in memory. Guarded finalization locks the source/context state, checks current order, qualified coverage, every required match disposition and current authority. It records completion and applies eligible absence/participation changes with required downstream revisions. Crash before finalization means no absence reconciliation; replay rereads/reintegrates the entire normalized observation idempotently. No download checkpoint engine or persistent list of every historical row.

The backend validates the designated source against the qualified competition context. HTTP success alone does not qualify context or completeness. No alternative source can establish or change professional authority.

Finalization applies absence consequences in one guarded local transaction after every required match succeeded. No empty-confirmation counter or failed-cycle input is required by F02.

| Observation for the same designated context                 | Sporting consequence                                                           |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------ |
| One complete successfully integrated empty current calendar | Hide pool, matches and participations, retaining IDs                           |
| Complete successfully integrated nonempty calendar          | Clear pool calendar-empty reason; reconcile attributable item presence/absence |
| Incomplete, stale, wrong-context or failed integration      | No absence reconciliation                                                      |
| Current manual rerun                                        | Same qualification and consequences as current scheduled work                  |
| New acquisition for a closed season                         | Refuse the operation; preserve authorized history                              |
| Nonempty qualified initial reconstruction before closure    | Correct data and reconcile attributable individual absences                    |
| No execution                                                | No observation or visibility change                                            |

Catalog absence is a separate attributable whole-catalog rule for the relevant season, independent of calendar emptiness. Discovery failure retains previously qualified same-season references if still eligible. An HTTP 200, empty CSV, all-rejected lines or requested season parameter do not establish completeness. Recognized byes/placeholders are contextual slots; they do not turn a nonempty incomplete calendar into a qualified empty one.

## Schedule and result values

Schedule is either unknown, a local date only, or a confirmed local date/time/timezone with its derived instant. Default covered metropolitan source zone is Europe/Paris. Invalid/ambiguous DST local times keep a date where known but no invented instant. FFVB 00:00 is unknown time unless explicit midnight evidence exists. No reliable kickoff means no rapid F01 window. F03 hides undated matches from public surfaces and owns device-zone/day presentation.

Result aggregate, finality (`FINAL`, `PROVISIONAL`, `UNCONFIRMED`) and detail are independent from match visibility. Official published results are final unless contrary indication; no elapsed-time or universal sets threshold. Each side may carry a recognized numeric or official `F`/`P` token; preserve `F/F`, `2/F` and other supported official presentations without deriving a winner. Unknown annotations stay bounded noninterpreted adapter diagnostics, not invented normal scores.

Ordinary set rows have source ordinal and known nonnegative points; validate their compatibility with the retained aggregate/context without recomputing an alternative score. Golden-set presence/points are separate. If detail is invalid or incompatible, hide that detail and preserve the useful aggregate and independent date/venue changes. If an aggregate changes, never retain old incompatible detail. If aggregate is unchanged and previously accepted detail remains demonstrably compatible, an invalid secondary field does not erase valid detail. Explicit authoritative result clear removes aggregate and associated detail/finality without declaring canceled/live. Repeated unchanged accepted result produces no new transition.

## Classification correction transaction

Resolve full requested pack/pool scope and complete target triple or inheritance removal. Check explicit action/scope permission and the current configuration revision. Lock the affected configuration, pools and team identities in stable order; ordinary match integration uses the same relevant fence. Compute all affected participations and identity keys before changing rows. Reject split, merge, target collision or affected out-of-scope participation with safe scope IDs/reason codes. Only then commit classification, preserved identities, acquisition inputs and dirty resource revisions together. Removing the sole acquisition classification leaves published classification intact and collection ineligible. Restoration must pass the same checks. Source updates cannot overwrite accepted operator configuration.

## Visibility and state transitions

Keep independent reason facts: pool catalog absence, pool calendar empty, division inactive; match/participation authoritative calendar withdrawal. Team visibility derives from at least one currently visible participation; clubs are not hidden merely because teams disappear or a division is inactive. F11 restrictions apply independently. A collector pause alone is never a visibility reason.

Public visibility is evaluated from current owning state at ordinary lists, details/deep links, feed, search-hit validation and map assembly. No undated match is publicly exposed under F03. Clearing one reason never clears the others. Catalog reappearance clears only pool source absence and can expose retained data if no calendar-empty or other reason remains; usable nonempty calendar evidence clears the empty reason; individual withdrawal persists until attributable authoritative calendar reappearance. Return reuses match/team/participation IDs without waiting for two observations. Closed-season history is not automatically hidden.

## Manual fields, logos and locality

Names keep independent full/short manual overrides and current source-derived values; clearing an override uses the current authorized automatic value. Club address, city, postal code, email, phone and website independently have `SOURCE`, `MANUAL`, `INTENTIONAL_ABSENCE` mode. Only `MANUAL` carries a manual value. F11 may suppress/delete any mode's content. No contact audit archive. Source collection changes current automatic slots without clearing manual modes. Operator revision is separate from source revisions so routine collection does not create artificial editing conflicts.

A logo command validates access before upload and rechecks access plus expected presentation revision before association commit. Fresh objects avoid overwriting V1/shared bytes. A lost response is reconciled through current association/version before a new upload. A failed upload/association leaves old presentation. Removing a team's override restores current club inheritance. F14 imports compare current import/association revision and preserve newer V2 edits; unresolved legacy associations remain protected in F14's manifest, not fictitious runtime clubs.

Every effective commune/postal change increments locality revision, clears the published point and exposes a new eligible need if sufficient context remains. Street-only changes do not. An absence/restriction may make context insufficient and suppress requests. The commune adapter returns matched municipal result, empty, ambiguous or technical failure for the exact request revision. Publish only a unique verified match and unchanged current context under transaction. Empty/ambiguous suppress automatic retry at unchanged context; technical failure follows F01 retry and retains a valid same-context point. No individual address/candidate history is introduced.

## F01 contextual-pool and lifecycle amendment

Ordinary youth qualifiers are ordinary pools with manually chosen regional/departmental division, format and gender. No progression relationship or promotion history is introduced. Compatible pools share an existing team identified by club, name, season, division, gender and format; one team follow covers these participations. Preserve F02 name comparison rather than V1 punctuation normalization. Distinct published groups reusing a code across tours have separate pool IDs, participations, calendars and ranking snapshots; an ordinary matchday does not split a pool. One qualified full CSV may supply several separately attributed observations, never one multipool absence scope. The source reference includes season/organizer/grouping/tour as required. Club references are strings and shared club numbers for different teams are expected. Team and pool identity never automatically crosses seasons.

Current LNV entry rollover is not authoritative absence from an older bound championship. F01 locks launched sources, preserving child discovery; initial historical reconstruction uses the existing idle provider slot while PREPARING, before definitive closure, without changing other seasons’ pause states. F02 retains its transactions and privacy/presentation guards. LNV detail freshness changes only when reread on the match's own eligible cadence; incompatible old sets cannot survive aggregate correction.

## Consultation source references

F03 adds three secondary source slots on the current match evidence: `informationSheet` (typed FFVB season/organizer/match descriptor), `scoresheet` (published qualified HTTPS URL), and `professionalMedia` (published qualified HTTPS URL). Their transport is defined in the internal observation contract. Retain current eligible KNOWN/explicit-clear state and provenance under the existing field rules; UNKNOWN/INVALID does not erase useful evidence or reject an otherwise identifiable match. Missing source icon alone does not establish explicit removal. No PDF bytes, permanent document history or video monitoring are stored. F11 restrictions still prevail.

The fixed information-sheet endpoint/form mapping belongs to F03's consultation adapter; acquisition only establishes descriptors from qualified evidence. Source-reference presence is independent of successful opening. A withdrawn result makes scoresheet presentation ineligible without clearing its retained reference. The official FFVB calendar URL remains on F01's qualified context reference, accessed through module composition rather than copied onto each match.
