# F02 observation integration contract

**Owner**: F02 sporting acceptance; F01 owns discovery, scheduling, issued cycles and acquisition diagnostics. **Trace**: FR-001–010, FR-017–044, FR-048–053. [OpenAPI snapshot](internal.openapi.yaml) is OpenAPI 3.0.3; its future source belongs to `contracts/internal/sport/`, included by F13's root. [Data model](../data-model.md) supplies invariants.

## Security, request limits and validation

Private network plus F13 service bearer credential; the public proxy must not route `/internal/v1`. The credential is not permission to invent cycle identity or source correspondence. Java validates strict types, required fields, no extra request fields, explicit state/value combinations and stored cycle/context agreement before integration. No provider URL supplied by a client is fetched by Spring; adapters use qualified provider references and allowlisted hosts.

One calendar observation per request, no list of calendars and no raw CSV/HTML. Configure an initial 16 MiB decoded JSON request bound, 100,000 maximum array items and bounded field strings as declared in the snapshot. These are defensive transport bounds, not a collection-volume target or permission to truncate. Qualification must show every enabled complete pool fits; an oversized legitimate scope blocks that adapter boundary for an explicit limit decision, rather than truncating, splitting it silently or calling it complete. Logo limits are separate. Streaming the HTTP request is an implementation detail, not a new chunk/resume protocol.

Snapshots define strict request objects and additive response objects. Conditional state/value requirements are semantic boundary validation, even where OpenAPI 3.0.3 cannot express them without problematic generator unions. Prove actual consumer behavior; do not assume annotations enforce it. Use the one F13 problem profile; the single local `sport-problem.schema.yaml` is a documentary projection, replaced by a reference to `contracts/shared/schemas/problem.yaml` on adoption, never two production owners.

## Calendar operation

`POST /internal/v1/sport/calendar-observations`, operation `integrateCalendarObservation`, consumes a `CalendarObservationInternalRequest` and normally returns 200 `CalendarIntegrationInternalResponse`, including partial outcomes. 200 means the response is a usable integration report, **not** that every match or the calendar succeeded.

| Input                                          | Required meaning                                                                                                                                                                                                                                                        |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| observationId / cycleId / cycleOrder           | UUID observation tied to a backend-issued F01 cycle and source/context order. Decimal order string avoids cross-language integer precision loss. Replay must reuse the same normalized content.                                                                         |
| source / context                               | `FFVB` for ordinary competition or `LNV_PAGE` for professional competition; qualified reference ID and backend season/pool IDs, provider context including round coverage where needed. Spring verifies these against discovery and correspondence evidence.            |
| observedAt / acquiredAt / optional publishedAt | Instants with offsets. Observation/acquisition are separate; publishedAt only when the provider states it. Backend records its own integratedAt.                                                                                                                        |
| coverage                                       | Complete/partial, qualified context reference, declared source row count, distinct reference count, source presence kind (`EMPTY`, `NONEMPTY`), essential coverage gaps and covered round keys. No automatic completeness from HTTP status or requested URL parameters. |
| matches                                        | Normalized identifiable entries, contextual byes/placeholders and local rejected entries. Repeated identical references collapse once; contradictory duplicates produce one rejected match, never last-write-wins.                                                      |
| field observations                             | `KNOWN`, `UNKNOWN`, `INVALID`, `CLEARED`; only known carries a typed value. Invalid has safe reason code; clear requires affirmative removal semantics for that field.                                                                                                  |
| anomalies                                      | Safe finite codes plus opaque item/reference identifiers; no referee/contact values, HTML, provider exception text or downloaded document.                                                                                                                              |

Mode and eligibility come from the stored cycle, not an unchecked `historical=true` flag. A valid earlier discovery can qualify the same-season reference after a catalog failure, but cannot bypass confirmed catalog absence or current operator restrictions. The backend still enforces current privacy, source hiding, inactive divisions and manual state at commit time.

### Admission and per-match result

Reject a malformed envelope, wrong source/season/pool, unknown cycle, mismatched order or globally unusable context before any sport write. Strict wire errors return 400; qualified business-context rejection returns 422; same observation identity with different content returns 409. A local participant/row failure belongs in the 200 report so other matches may commit. If no match reference can be established, `referenceKind=LOCAL_REJECTION` carries a stable local row key only: the backend rejects that entry, never treats the key as sporting identity, and forbids absence reconciliation. Attributable references use `ATTRIBUTABLE`. A recognized future qualifier/bye is `CONTEXT_ONLY`, not a fake team or malformed participant.

Essential evidence is source context/reference, attributable match identity and two certain participants/club/classification for a publishable encounter. A calendar must retain source slot/reference accounting so filtering cannot manufacture an empty calendar. Date, start time, venue, allowed referees, aggregate result and set detail are secondary when identity/presence is otherwise established. Missing or invalid secondary detail alone does not make calendar presence incomplete. Preserve usable fields and report a warning; an undated match remains internally accepted but not publicly consultable under F03.

For each distinct match, an explicit Spring application operation commits identity/correspondence, teams/participations as needed, accepted useful fields, current restriction checks and owned downstream work in one PostgreSQL transaction. The loop itself has no enclosing all-calendar transaction. A failing match rolls back only its transaction; the report identifies its disposition. A catastrophic database/transport failure can lose the report after earlier commits: return safe 5xx if possible and treat outcome as uncertain, not zero commits.

| Response field                                        | Meaning                                                                                                                                     |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| status                                                | `COMPLETE` or `INCOMPLETE`; complete requires every necessary identity/presence item processed successfully and globally qualified coverage |
| accepted / unchanged / rejected / contextOnly / stale | Counts of distinct entries, not duplicated source rows; invalid secondary warnings do not count as rejected match                           |
| items                                                 | Reference, disposition, optional stable match ID and safe reason codes; unchanged includes identical replay with no new sporting effect     |
| authoritySource / absenceReconciled                   | Validated designated source and actual successful absence reconciliation. No empty-confirmation count or authority election.                |
| diagnosticId / integratedAt                           | Opaque technical reference and backend report time; safe for F01 operator diagnostics                                                       |

Counts equal the number of normalized distinct reference entries, including rejected/context-only/stale dispositions. Reported sourceRowCount may be larger because repeated representations/identical duplicate rows are collapsed. No outcome is silently omitted. Per-field observation times are supplied when detail acquisition differs from the envelope; missing provider publication times remain unknown. Unrecognized score notation may remain a bounded nonpersonal token on an invalid result observation, never arbitrary source text. The summary and field warning codes distinguish accepted sports changes from full synchronization.

### Finalization, ordering and replay

Use the source/context fence described in the data model on **both** match writes and finalization. Older work may not replace a newer accepted state or withdraw against its presence. The current observation digest prevents changed replay under the same identity. Semantic equality ignores transport retry time and does not create a new sporting change, indexing revision or notification transition.

Finalization requires complete qualified presence coverage, no essential gap, no local match rejection/staleness/transaction failure, and an eligible current authority decision. A supplementary ranking or bad sets-only detail cannot invalidate otherwise complete calendar presence. A failed essential per-match fetch can, if identity/presence was not established from the grouped calendar. Do not label all enrichment failures either universally fatal or universally harmless.

Absence reconciliation is confined to the explicitly covered pool/phase/round scope. A reused FFVB pool's incomplete round export cannot withdraw other rounds. A calendar containing recognized placeholders is nonempty source context, not `EMPTY` because zero public matches remain. Known source slots and their verified prior references determine only attributable absences; uncertainty is an essential gap, not permission to delete.

Apply the [model state table](../data-model.md#calendar-state-order-and-finalization): one qualified wholly empty current observation hides pool, matches and participations; a still-listed hidden pool remains collected. Qualified nonempty reappearance clears only its own reason. No scheduled confirmation counter or secondary-source sequence exists. Closed seasons reject new acquisition; only already running cycles may finish once under F01. Initial historical emptiness preserves history; qualified nonempty input may reconcile individual absences before closure.

A lost response is retried only by the owning F01 policy with the same immutable observation or by the next eligible cycle. No general download recovery ledger is added. Replaying a newer superseding cycle is ordinary acquisition, not proof the previous request rolled back. Repeat testing must show stable IDs, no additional sporting transitions and safe old-order refusal.

## Qualified F01 scope amendment

The F01 cycle references a launched seasonal source binding or explicitly validated historical context. Current LNV entry rollover is not catalog absence for another stored season. Only a complete catalog of the affected bound scope can withdraw its source eligibility. A tour page is not a whole-season catalog.

One calendar observation addresses one Blockout contextual pool. Shared FFVB CSV downloads may be partitioned only for a demonstrated format; `coveredRoundKeys` is empty for ordinary pools or exactly the distinct-group tour of that pool. No universal Jo-to-tour rule or prefix-based attribution is valid. F01 has no closed-season recollection operation. F02 checks issued-cycle eligibility: only a cycle already running at closure may finish once. Initial historical corrections occur before closure; wholly empty/unavailable initial archives preserve retained data. Initial reconstruction remains silent under F07.

## F03 external-reference enrichment

`informationSheet`, `scoresheet` and `professionalMedia` follow existing secondary state/value/provenance rules. All three fields are present in normalized observations; unqualified or unobserved values use UNKNOWN. Validate descriptor context against the match and validate URL destinations without downloading the media/PDF. A bad secondary reference records a safe warning and does not reject identified presence. Actual explicit removal can clear the owning slot; absence of an icon is not sufficient. Retain references independently of result finality and let F03 apply presentation eligibility. Source order, privacy and stale-write fencing remain unchanged.
