## PDF transport and reading

**Decision**: The backend relays the qualified document on demand, outside SQL transactions, using bounded ordinary HTTP requests and the accepted source reference. It accepts no arbitrary client URL. The mobile downloads through its shared transport with cancellation, writes a temporary Expo FileSystem file and displays that local URI with `react-native-pdf` 7.0.5. Remove temporary files on close/failure and leftovers at cold start; no offline archive, export workflow, token renewal, job or automatic retry is added.

The relay uses the existing OkHttp 5.2.1 dependency with connection retries and native redirects disabled. Its [status follow-up implementation](https://github.com/square/okhttp/blob/parent-5.2.1/okhttp/src/commonJvmAndroid/kotlin/okhttp3/internal/http/RetryAndFollowUpInterceptor.kt) can still repeat a `503 Retry-After: 0`. A supported [network interceptor](https://github.com/square/okhttp/blob/parent-5.2.1/docs/features/interceptors.md#network-interceptors) therefore closes and rejects terminal HTTP errors before that decision; controlled GET and form-POST cases require a single request and the ordinary unavailable outcome. This is a refusal at the native transport boundary, with no retry loop or recovery owner.

**Rationale**: [react-native-pdf 7.0.5 source](https://github.com/wonday/react-native-pdf/blob/v7.0.5/index.js) supports direct PDF viewing on both platforms. Its inspected 7.0.5 download implementation retains cache files even with `cache: false` and does not actively cancel its download on unmount. Keeping network ownership in the common transport avoids relying on those behaviors. The reader receives a local file only. [Expo FileSystem](https://docs.expo.dev/versions/latest/sdk/filesystem/) provides cache files, byte writes and deletion; [Expo Fetch](https://docs.expo.dev/versions/latest/sdk/expo/) supplies the standard transport building blocks.

On the installed Expo Fetch/RN 0.88.1 combination, binary responses use React Native's Blob, which lacks `arrayBuffer()`. The temporary-file adapter therefore uses the installed native `FileReader.readAsArrayBuffer`, with the same request signal, rather than adding a Blob dependency or bypassing the generated transport. The full-screen Modal supplies its own [SafeAreaProvider](https://appandflow.github.io/react-native-safe-area-context/docs/api/safe-area-provider/); native top and bottom insets own the header and PDF viewport without a manual inset controller.

**Alternatives**: System external readers do not guarantee reading without another installed application. A Google Drive viewer adds a third-party dependency and disclosure of the source URL. A custom PDF renderer or patched dependency would duplicate supported native rendering.

**Evidence limits**: The examined supporting package was `react-native-blob-util` 0.25.1. Published config plugins 14.0.2 declare Expo >=56 compatibility; unpublished repository versions are not selected. Both native debug builds and bounded simulator/emulator rendering and cleanup pass on Expo 58.0.22/RN 0.88.1, with the [construction evidence and remaining cases](quickstart.md#match-document-construction-and-pending-qualification--t047t058). Physical-device compatibility and representative source-relay qualification remain T058 before accepted adoption. Failure reopens this boundary rather than authorizing a fork or a changed minimum platform.
