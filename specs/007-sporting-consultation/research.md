## PDF transport and reading

**Decision**: The backend relays the qualified document on demand, outside SQL transactions, using bounded ordinary HTTP requests and the accepted source reference. It accepts no arbitrary client URL. The mobile downloads through its shared transport with cancellation, writes a temporary Expo FileSystem file and displays that local URI with `react-native-pdf` 7.0.5. Remove temporary files on close/failure and leftovers at cold start; no offline archive, export workflow, token renewal, job or automatic retry is added.

The relay uses the existing OkHttp 5.2.1 dependency with connection retries and native redirects disabled. Its [status follow-up implementation](https://github.com/square/okhttp/blob/parent-5.2.1/okhttp/src/commonJvmAndroid/kotlin/okhttp3/internal/http/RetryAndFollowUpInterceptor.kt) can still repeat a `503 Retry-After: 0`. A supported [network interceptor](https://github.com/square/okhttp/blob/parent-5.2.1/docs/features/interceptors.md#network-interceptors) therefore closes and rejects terminal HTTP errors before that decision; controlled GET and form-POST cases require a single request and the ordinary unavailable outcome. This is a refusal at the native transport boundary, with no retry loop or recovery owner.

**Rationale**: [react-native-pdf 7.0.5 source](https://github.com/wonday/react-native-pdf/blob/v7.0.5/index.js) supports direct PDF viewing on both platforms. Its inspected 7.0.5 download implementation retains cache files even with `cache: false` and does not actively cancel its download on unmount. Keeping network ownership in the common transport avoids relying on those behaviors. The reader receives a local file only. [Expo FileSystem](https://docs.expo.dev/versions/latest/sdk/filesystem/) provides cache files, byte writes and deletion; [Expo Fetch](https://docs.expo.dev/versions/latest/sdk/expo/) supplies the standard transport building blocks.

On the installed Expo Fetch/RN 0.88.1 combination, binary responses use React Native's Blob, which lacks `arrayBuffer()`. The temporary-file adapter therefore uses the installed native `FileReader.readAsArrayBuffer`, with the same request signal, rather than adding a Blob dependency or bypassing the generated transport. The existing reader’s download/file operation and native decode callbacks retain lifecycle ownership. A first active load uses the shared skeleton. After failure, explicit Retry intent retains the Error Card while those same native owners re-enter loading; actual operation progress alone occupies its button. Keep Close/Return usable, renewed failure retryable and temporary-file cleanup unchanged. Profile, Support and sporting-editor image fields use passive media without an enlarged viewer; their owners retain selection, drafts, files and authorization. Optional row/identity artwork uses its nominal fallback without expanding notices. No new media manager, download controller or generic recovery abstraction is justified.

The full-screen Modal supplies its own [SafeAreaProvider](https://appandflow.github.io/react-native-safe-area-context/docs/api/safe-area-provider/); native top and bottom insets own the header and PDF viewport without a manual inset controller.

**Alternatives**: System external readers do not guarantee reading without another installed application. A Google Drive viewer adds a third-party dependency and disclosure of the source URL. A custom PDF renderer or patched dependency would duplicate supported native rendering.

**Compatibility limits**: The selected supporting package is `react-native-blob-util` 0.25.1. Published config plugins 14.0.2 declare Expo >=56 compatibility; unpublished repository versions are not selected. T058 validates functional opening, cancellation, representative renderer failures and cleanup on compatible native clients under the [selected F13 runtime scope](../003-shared-quality/plan.md#technical-context) and [proportionate qualification](../003-shared-quality/plan.md#proportionate-qualification), using the [document scenarios](quickstart.md#match-document-cases). Retain a consolidated physical candidate smoke for actual rendering/touch and interruption/termination cleanup; deterministic transport tests own exhaustive relay/access/ordering cases. Representative authorized source-relay evidence remains distinct from controlled binary responses, and exact signed-release/upgrade proof stays with F13/F14. Missing physical/source evidence remains pending before accepted adoption. Failure reopens this boundary rather than authorizing a fork or a changed minimum platform.
