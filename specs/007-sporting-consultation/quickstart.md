### Native time presentation — T019/T021

The dedicated `sporting-time*.test.ts(x)` suites exercise the exact A07 instant (September 20, 2026 00:30 Paris / September 19 18:30 New York), date-specific DST offsets, unchanged date-only values, unknown FFVB 00:00 versus confirmed midnight, and French relative labels. Component tests use the actual match summary/detail, providers and generated response decoder; HTTP, native identity, clock and default device zone are controlled. Foreground presentation updates independently of a network read.

The calendar input test uses generated requests and the real Query cache with controlled pages. Formatting in a changed display zone leaves the captured grouping zone, returned day groups and exclusive continuation inputs intact. It proves those inputs only: there is no implemented native calendar, navigation, reordering or scroll-reset qualification here. T020/T022 require the actual PostgreSQL calendar query; T023 requires the subsequent native iOS/Android calendar and travel scenarios.

Implementation uses the installed Expo 58.0.19 / React Native 0.88.0 runtime's ordinary `Date` and `Intl.DateTimeFormat` facilities, with no added package, source-time reconstruction or product setting. The installed RN Hermes source tag `hermes-v260318099.0.2` exposes [`formatToParts`](https://github.com/facebook/hermes/blob/hermes-v260318099.0.2/lib/VM/JSLib/Intl.cpp); [ECMA-402](https://tc39.es/ecma402/#datetimeformat-objects) defines time-zone/date-component formatting, and the native [`AppState` change event](https://reactnative.dev/docs/appstate#change) owns foreground notification. UTC date carriers are used only to format/compare calendar dates, never to assign a sporting instant. Native rendering evidence and its exact revision belong in the delivery PR; Node/Jest Intl results alone do not qualify Hermes or the full device matrix. Shared live Dynamic Type (#433) and iOS 17 input (#449) remain deferred independently.
