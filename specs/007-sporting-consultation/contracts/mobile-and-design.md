# F03 mobile interaction and design contract

## Navigation and queries

Thin Expo Router resource routes resolve exact UUIDs; feature screens own tabs, local selection and queries. Do not implement a parallel router or resource-name lookup. Reuse F13's app shell and approved tabs. Club selected season is shared by its Teams/Upcoming/Completed tabs; team and pool IDs already have a sporting season. Preserve selection when still offered by a reliable season-list read, including closed history; only confirmed disappearance selects the most recent remaining season or none.

A new page entry reads common detail plus its initial tab. Opening an unloaded tab fetches its endpoint; returning to a loaded tab in the retained screen keeps its state. Pull-to-refresh targets the active tab only. For club Information this is the club detail endpoint, so its common information/season choices may change. For pool/team standings, calendar and map, do not refresh common header or sibling tabs. F06 counts/private state are separate owner queries; a sport refresh is not a claim that these were refreshed.

For calendars and club teams, disable focus/reconnect/mount refetch of retained instances and use invalidation without immediate refetch. Explicit new-route entry starts a new loading generation even if an old cache value can be displayed while waiting. No new-route opening should silently promise the old value is current. Match detail rereads on focus/foreground/manual refresh, coalescing overlapping triggers into one in-flight query. A fresh match result does not automatically rewrite/reorder the retained parent calendar.

Calendar refresh cancels/ignores append work, retains the old chain, reads only the first page in the current timezone, validates it, then replaces pages/pageParams together and scrolls to the beginning. Failure preserves authorized old data with the existing refresh-failure indication. A previous-generation success cannot append or clear a current error. More-page failure uses the existing retry affordance and retains loaded rows. Never infer no-more-data from client deduplication; use server cursor presence.

Known resource/field restrictions immediately suppress controlled old cache values. This is the deliberate exception to stable rows; preserving a visual position cannot republish forbidden content. F05 generation guards private owner queries and abandoned document requests. Do not put accounts, tokens or document bytes in public query keys. No calendar polling, process-restart persistence or rechecking F12 on foreground.

## Time and result presentation

Render established instants in the current phone zone, respecting the offset at that instant. Render date-only sporting dates without conversion and with the approved unknown-time indication. Relative day labels are based on the day group and its loading zone; after travel, a converted row hour can temporarily disagree with its retained group date. Do not add a special travel banner or regroup the list. Refresh reconstructs groups in the current zone.

Apply F03 classification on each current server read. Retained calendar rows keep that category. Completed without aggregate shows the approved unavailable-result indication; provisional result stays explicitly provisional. A definitive result may precede H+6. Do not infer live, winner, cancellation or replay. Keep overall result usable when detail is invalid. Expose set-detail modes and information panels already in the approved match journey; no result editor.

## Native document adapter

Use one feature adapter for explicit PDF actions; its transport distinguishes Blockout relay from qualified direct provider URL. Refresh current match detail before starting a scoresheet action; apply current definitive-result and reference requirements. Blockout relay also rechecks viewability after supplier retrieval. F13 errors and typed F12 maintenance refusal are handled before handing any file to the OS. A failure on one document does not hide independent sporting facts.

Write validated binary bytes only into an opaque-named temporary file under the app cache directory. Use a small local Expo iOS module exposing Quick Look preview of that owned file, with completion on dismissal; no generic arbitrary file access or custom PDF rendering. Android uses expo-file-system contentUri, ACTION_VIEW, application/pdf and temporary read permission through expo-intent-launcher. Do not pin a reader package or request broad storage permission. Missing viewer, unavailable preview or corrupt file leaves an actionable error and return/retry, without an invented expiry diagnosis.

Native completion controls cleanup; do not delete while a reader still needs the file. Cancellation removes partial downloads; cold start removes abandoned files in the owned temporary subdirectory. Session/context changes abort downloads and prevent late native handoff. Where a viewer is already open, stop new operations and clean after its return; do not promise recall of a file already handed to another application. No timers/persistent download ledger are added. System reader launch is not proof of successful rendering.

Stream and ordinary website links use the established external-opening adapter. Calendar links use qualified source URLs. Phone/email/navigation actions require usable permitted destinations, never a geographic search invented from missing venue.

## Map and list rendering

Use FlatList/SectionList with stable match UUID keys and day/pool keys. Flatten pool headings into virtualized rows or sections so a large day is not rendered as one unbounded nested ScrollView. Keep row subscriptions narrow, text scaling supported and selection outside recycled row-local state. No fixed row height assumption for enlarged text and no new animation/reconciliation framework.

react-native-maps uses Apple Maps/Google Maps under the accepted architecture. Group exact shared municipal points and reuse the approved selected-team panel and per-team controls; never displace coordinates. Ranking-derived information in that panel is optional and unavailable independently. Frame reliable points using provider map controls; a single point uses a municipal view, never an asserted venue. No GPS request, auto recenter on every unrelated render or user-position marker.

Distinguish data-loading failure from map tile/provider failure when native evidence establishes it. Do not manufacture a tile timeout/status from a timer. Retain known points and the accessible selection information when the basemap cannot render. Expo Go alone does not qualify real Google Maps configuration or production signing restrictions.

The owner-approved plan explicitly accepts stable retained lists, active-tab-only refresh, travel's retained-group limitation and direct PDF. Their walkthrough maps to the same existing layouts; there is no new screen requiring canonical translation. If implementation exposes a material new state/layout or unavailable library capability, stop that affected design boundary for revalidation instead of silently redrawing it. Do not certify prototype screenshots as Quick Look/Android/map-provider behavior.

## Native acceptance

Check light/dark, 320/375 widths, large text including 200%, screen-reader names/order, focus restoration, 44-point targets and reduced motion for affected existing states. On real iOS/Android verify scrolling with headers/long names, back/foreground preservation, successful reset, failed-page retry, map panel at enlarged text and PDF cancellation/return. No unrun benchmark or promised frame rate substitutes for these functional checks.
