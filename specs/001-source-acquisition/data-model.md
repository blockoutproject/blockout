# F01 acquisition data model

This describes future Spring-owned persistence; no schema or migration is executed. F02 owns sporting seasons/resources and observations, F12 permissions, F13 operations. Use normal foreign keys, unique constraints and optimistic revisions, not a generic workflow or polymorphic event store.

## Reference and identity boundaries

Ordinary example: `FFVB / 2026-2027 / ABCCS / 3FA`. Reused-group example: `FFVB / 2026-2027 / ORGANIZER / CHAMPIONSHIP / phase02 / A`. These synthetic examples illustrate the context tuple for covered championships, not a promise that all providers share a textual-key algorithm. Preserve case-sensitive source values. Store provider fields separately and serialize a canonical context key in the owning adapter with explicit escaping, not display-name concatenation.

Each distinct proven group/tour is a separate F02 pool. Its source round is part of correspondence, not a new qualification type. Compatible pools can reference the same F02 team identity (club, name, season, division, gender, format); no progression relationship or follow transfer is inferred. A matchday is retained on the match. Same-calendar CSV download identity and each published observation's pool identity differ. F02's `coveredRoundKeys` is empty for an ordinary pool and contains exactly its qualified round for a contextual round pool; one observation cannot span several Blockout pools.

Clubs are persistent and club numbers are strings. Teams/pools are seasonal; team identity remains `(club, season, division, format, gender, significant name)` under F02. No previousTeamId, promotedFromPoolId, inferred qualification graph or automatic follow transfer exists. Known participant placeholders stay source observations, not fictional teams.

## State and concurrency rules

Before launch, an operator can change a supported source URL using its current revision; this invalidates prior qualification/confirmation. Validation snapshots that revision. A late validation response cannot qualify a subsequently changed binding. Explicit season confirmation is recorded against the same revision. Launch atomically verifies source qualification, seasonal attribution, covered scope and permissions, then locks affected sources. Mapping completeness is not a source-launch condition; launch does not create or change mapping data. Child discovery uses the locked parent, without modifying it. Pausing or closing never clears lockedAt.

Public mutations carry expectedRevision; stale requests return 409. Reads resolve uncertain outcomes without repeating mutations. Initial reconstruction requires PREPARING, qualified references and the idle provider slot; it locks its references. Validation requires an unlocked preparing binding and idle provider slot, but need not enable periodic collection. Closing is terminal and requires the exact displayed season label plus expectedRevision. Atomically prevent new cycle starts and cancel unstarted requests; only cycles already RUNNING at acceptance may finish their selected work once, under normal F02 ordering/visibility guards. Preserve data and source locks. No reopen, recollection or source validation is available after closure; reads remain available. Other season/provider and seasonless club controls are unchanged. A lost response requires a read, never an automatic repeat.

Collector registration increments a backend process generation after the old process is stopped under F13; old running cycles become INTERRUPTED and old-generation writes are rejected. This is a restart fence, not an automatic supervisor or lease. A new process starts ordinary eligible cycles and does not reconstruct old download progress. F02 cycle order and replay semantics remain mandatory.

Configurations and needs are read in bounded pages using current revision and stable UUID order. Changed revision returns 409; restart selection, never combine different revisions. Start-cycle atomically checks the completed selection's revision. The collector retains the selected immutable configuration for that run; source acquisition changes take effect next cycle, while current F02 visibility/authorization fences remain authoritative.

## Transactions and retained data

Season launch, typed terminal closure, scoped family commands, source preparation and acceptance of qualified discovery each use one bounded Spring transaction. Provider HTTP never runs inside it. Sporting integration remains F02's match transactions and separate absence finalization. A discovery publication must name its exact complete scope before omission can mark a child reference absent. Current-root rollover cannot retract children of a different stored seasonal championship.

Operational metadata follows F13/F11 minimization and retained error evidence, without a new raw-history retention subsystem. Migrations follow F02: baseline may be reworked only while all affected data is reconstructible; first preproduction or earlier retained data freezes executed history.

## F03 consultation additions

A published season candidate records `startYear` only when its source attribution establishes chronology. For a recognized published `YYYY/YYYY+1` or `YYYY-YYYY+1` range, use its first year after validating the range and context; do not infer it from match dates or synthesize next season. Preparation resolves the stored candidate year into the canonical F02 season. Unresolved chronology blocks preparation with a safe explanation; no additional free-form ordering control is introduced. Administrative season projections expose the canonical year while preserving the exact label used for closure confirmation.

Keep the public official-calendar `sourceUrl` on the qualified contextual reference and expose it through the acquisition application API for F03 composition. Do not duplicate it per match. The existing FFVB/LNV provider branches may supply attributable information-sheet descriptors, actual scoresheet links and actual professional-media links through the extended F02 observation contract. Treat them as secondary enrichment: missing or invalid reference does not invalidate match presence or complete-calendar coverage. Do not fetch PDF bytes during collection or add a LNV TV discovery service.
