This is a future qualification guide, not executable runtime instructions for the documentation-only tree. No application or dependency is initialized here.

## Prerequisites and order

Obtain dossier acceptance, targeted [visual supplement](visual-supplement.md) approval for changed UI, global plan approval and authorized implementation tasks. F13 must first remove the planning rewrite exception and restore administrator branch protection, then initialize locked native-tool targets and test infrastructure. F02 provides sporting contracts, identities, transactions and privacy/visibility rules. Do not copy historical V1 commands into this tree.

Use a disposable local/staging environment with isolated PostgreSQL/OpenSearch, synthetic authorized accounts and controlled provider fixtures. Enable limited live provider reads only for the scope being qualified; never write to provider systems. Create no production data or account migrations for this guide. Use the actual future committed Nx/npm, Maven and uv targets selected by F13; they do not exist here yet.

Run pure parser/clock/HTTP cases first, then real contract consumers and database transactions, then native/visual/provider/staging evidence. Record revision, scope, method, expected/actual outcome and limits for each case. A failure blocks only its affected capability unless it violates a shared integrity or security boundary.

## Documentary checks executable now

Use the repository-authorized pinned formatter on Markdown and relevant contract YAML, check local links/anchors and OpenAPI references/operation/security/schema structure, and run `git diff --check`. Run official Spec Kit prerequisite and analysis procedures against the feature. These checks do not execute V01–V14 or approve checklist markers.

Preserve exact provider codes/tokens needed by a case while reducing/anonymizing examples. No raw downloaded pages, referee identities or personal-contact archive belongs in fixtures. Distinguish observed samples, historical manuals and synthetic negative controls. No automatic fixture refresh.

## Failure response

A provider capability not demonstrated remains unqualified. Do not substitute a different source, guess a season/identity, build a custom supervisor or silently change cadence. Return a material incompatibility or changed product/visual requirement to its owner. Closed history remains protected, and F14 decides whether missing coverage prevents cutover. No benchmark or availability-accounting work is hidden in qualification.
