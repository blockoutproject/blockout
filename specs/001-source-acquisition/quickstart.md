# Validation guide: acquisition and source operations

Follow the [local development setup](../../README.md#local-development) and run the [repository verification commands](../../README.md#verification). Use the prerequisites and scenarios below to qualify acquisition end-to-end; shared checks alone do not establish provider coverage or complete acquisition/integration.

## Prerequisites

Use an isolated environment with the backend, PostgreSQL and single collector instance, generated consumers from the same [canonical contracts](contracts/README.md), a collection-authorized operator and accounts without that right. Prepare deterministic sanitized/synthetic FFVB, LNV and IGN fixtures, controlled transport responses and a controllable test clock. No personal provider payload belongs in Git. Live-source qualification requires its own authorized scope and is not a CI dependency.

## Discovery and professional adapter checks

The collector suites `FfvbDiscoveryTest`, `DiscoverSeasonSourcesTest`, `QualifySourceTest`, `LnvObservationsTest`, `LnvHttpCachingIntegrationTest`, `LnvObservationReaderTest` and `CollectPassageTest` exercise native contexts, refusal/partial behavior, clocks, generated identity handoff and controlled HTTP caching. The backend's source-preparation and match-detail integration suites exercise the current-incarnation fence and established document associations against migrated PostgreSQL. Run the repository's full verification to include generated producer/consumer compatibility; these tests establish their represented boundaries, not exhaustive provider coverage.

Discovery consumes shared pages immediately for already admitted scopes and retains no page reserve. Regression cases distinguish a season header from an actual catalog, reject an isolated round as a seasonal root, preserve contextual Cup exclusions and unrelated roster failures, and retain document refusals across independent successful details. The auxiliary-index test verifies one read across pools with its original timestamp and ordinal. Other regressions cover contradictory seasons before shared-page consumption, redirected document identities, championship standings without a phase query, partial date/result fields, native forfeits and independent current-menu failures.

Generated target mapping retains exact references and current locality revisions. Confirmed admission supplies the immutable candidate directly; qualification publishes once. A lost admission response starts no provider work or confirmation read, and later polling follows backend eligibility. Conflict inspection preserves the original refusal when its read is unavailable and stops confirmed supersession. Reader/parser cases preserve image-cache provenance, exact scoped document matching, incomplete detail evidence and the same auxiliary-index value or failure for every pool in one passage; the next passage starts fresh.

Verified document-team associations remain explicit configuration scoped to season, championship and native team. Empty configuration leaves auxiliary XML codes unavailable. No test fixture, sampled current identifier or ordinary discovery run supplies missing historical associations or activates collection. Actual provider qualification, native operator journeys and scheduling remain with their owning tasks.
