# Validation guide: acquisition and source operations

Follow the [local development setup](../../README.md#local-development) and run the [repository verification commands](../../README.md#verification). Use the prerequisites and scenarios below to qualify acquisition end-to-end; shared checks alone do not establish provider coverage or complete acquisition/integration.

Native accessibility verification follows [F13 FR-030](../003-shared-quality/spec.md#platforms-accessibility-and-bounded-continuity).

## Prerequisites

Use an isolated environment with the backend, PostgreSQL and single collector instance, generated consumers from the same [canonical contracts](contracts/README.md), a collection-authorized operator and accounts without that right. Prepare deterministic sanitized/synthetic FFVB, LNV and IGN fixtures, controlled transport responses and a controllable test clock. No personal provider payload belongs in Git. Live-source qualification requires its own authorized scope and is not a CI dependency.

## Boundary evidence

Qualify the changed acquisition boundary using the runnable scenarios below and the [shared F13 qualification rule](../003-shared-quality/plan.md#proportionate-qualification). Existing suites identify supported checks; their presence is not whole-feature, source-inventory or transition acceptance. [Tasks](tasks.md) retain completion ownership. Diagnostic qualification combines local backend/collector checks with useful native inspection of current result projections; neither boundary completes the other implicitly. Exact executed revisions, build identifiers, command outcomes and review captures belong in normal delivery evidence outside `specs/`.

Use these evidence meanings consistently:

- **Controlled**: deterministic clock, HTTP, identity or source inputs exercise real handwritten logic. PostgreSQL and cross-process suites additionally exercise migrated tables, generated HTTP consumers and actual owner transactions. Synthetic supplier input remains synthetic even when the backend and database are real.
- **Observed supplier sample**: an authorized read or provider-backed rehearsal demonstrates only the selected source, season, phase, fields and response form. The [source observations](research.md#ffvb-source-patterns), [professional observations](research.md#lnv-coverage-time-and-images) and [geocoding observations](research.md#club-geocoding) retain their format and availability limits. No sample inventory or identifier is a permanent coverage contract.
- **Observed native**: an installed simulator/emulator development client exercises the delivered routes and interactions. A controlled identity or loopback supplier in that run does not qualify hosted identity or a live supplier. Reuse retained evidence only while its affected behavior remains unchanged.
- **Unavailable or outside the exercised scope**: no successful result is inferred. Keep the missing source, runtime or consumer qualification visible rather than replacing it with a fixture, a document check, startup or a JavaScript export.

Use [repository verification](../../README.md#verification) for generation/build/test checks and the explicitly disposable [collector-to-sporting runtime](../../README.md#collector-to-sporting-qualification) for opt-in cross-process cases. A skipped opt-in suite supplies no execution evidence. Add `CollectorUncertaintyIntegrationTest` and `CollectorPresentationBoundaryIntegrationTest` to that command's `-Dit.test` selection when exercising their cases, keeping its migrated disposable database, restricted application role and explicit runtime settings.

Supplier observations and their dates, exact functional URLs and format limits remain in [research.md](research.md). They support only the inspected sources and fields, not complete catalogs, archives or future structures. Controlled identity and supplier responses on a native client do not qualify hosted authentication, live suppliers or external push.

Native evidence is reusable only for unchanged source, native dependencies, configuration and runtime. The unavailable iOS 16.4 floor, live iOS text resizing and physical/store candidates retain their F13/F14 owners. F03 retains Map physical/configuration checks and the explicit Android provider hold; bounded Android partial-map observations do not lift that hold. F14 owns actual reconstruction, protected-logo preservation, unavailable-history acceptance and cutover authorization.

## Discovery and professional adapter checks

Run the backend and collector targets from [repository verification](../../README.md#verification). Use controlled source/HTTP responses for refusal, partial-result, clock and cache cases; run provider qualification separately with authorized current and historical sources.

Verify seasonal attribution before consuming a shared catalog. Reject isolated rounds used as seasonal roots, contradictory seasons and unrelated championship contexts. Shared indexes are read once per passage and retain their original timestamp/ordinal; failures remain failures for every affected pool until the next passage. Preserve exact document-team associations scoped to season, championship and native team. Empty configuration supplies no auxiliary XML code or historical association.

Confirm admission before provider work and allocate ordinals before reads. A lost admission response starts no provider work or confirmation read; later polling follows backend eligibility. Conflict inspection preserves the original refusal when unavailable and stops confirmed supersession.

### Source preparation and seasons

Use controlled official-entry and catalog fixtures, the normal collector scheduler and generated consumers against isolated migrated PostgreSQL. Select supported reference formats through the [source policy](research.md#ffvb-source-patterns).

1. Begin without a season or provider control. Discover qualified FFVB and LNV roots through the normal current entry reads. Keep the season PREPARING and all pools unmapped. On a due catalogue pass, verify actual FFVB packs/pools and LNV phases for all three official championships, with qualified official URLs. Verify zero dedicated calendar/standings imports. Change one official championship catalog to attest a new supported phase, then verify its presence on a subsequent due pass without a source edit or activation.
2. Compare an unsupported phase structure, wrong season, wrong organizer/championship, partial read and failed transport. Check the latest read status, original time, factual reason when available and prior complete timestamp in the generated source response. Earlier entries, mappings, visibility and independent source results remain. Without a previous complete read, no partial entry is added. A complete authoritative observation reconciles addition, absence and reappearance inside its scope. Verify retained UUIDs and mapping, no cross-season change and no clearing of an unrelated calendar-empty or division reason.
3. Activate the season with current `collection.manage`. Refuse an unauthorized request and activation of a closed season. Repeat activation successfully without additional effects. Verify the same mappings and independent provider pause state. Select a complete individual classification under an unclassified pack and verify the next eligible ordinary passage selects only the mapped pool with effective division activity and a present qualified reference.
4. Repeat with simultaneous active seasons, a paused provider and a current LNV entry that has rolled to another season. Compare independent bindings, controls and observations. Keep a historical reference prepared through the isolated command below. Verify that a pending initial request retains its selection and blocks activation, and that activation can proceed after admission without changing the historical passage.
5. Exercise the deprecated generated mobile source writes with a current grant and without it. Verify the business conflict for authorized valid requests, authorization refusal for unauthorized requests and no source or season effects. Verify the existing catalogue and unfiltered Bilan reads still work with their generated consumers.

Use the [approved compositions](plan.md#design-acceptance) for the native read-only catalogue and season activation journey. Confirm that application read failure uses its scoped card and Retry, while provider unavailability inside a successful application read can show retained entries and the last complete read. Qualify live provider content and native interactions at their actual boundaries.

### Professional sources

Select current championship roots from the [official LNV entries](research.md#lnv-coverage-time-and-images) and historical roots from their published archive links. Follow each root's published regular/playoff phases without guessing identifiers. For controlled historical references, exact-season confirmation may supply missing attribution after structure and scope checks. Ordinary discovery requires provider attribution and a supported published structure before exposing a phase.

Run the ordinary collector and F02 acceptance with periodic controls disabled for the isolated reconstruction. Read every F03 calendar page and compare exact match/team/pool/season identities, participant links and official standings. Expect no duplicate traversal identity or cross-season association. A bracket without a published standings table remains `not-published`; its calendar and participants remain usable.

Verify scoresheet/statistics references and the document-only information-sheet associations separately. Historical facts never come from current XML. Unavailable-file notices supply no replacement locator; unknown missing links remain structural refusals. Public F03 actions expose Blockout subresources without supplier locators, and collection fetches no PDF body.

Compare pinned-offset calendar/detail clocks, date-specific Europe/Paris conversion, partial dates, unknown-time flags and UTC date changes. A later supplier correction remains authoritative under the accepted logical ordering. Use the [F03 document boundary](../007-sporting-consultation/plan.md#maps-and-documents) for native relay/reader behavior. Representative sources establish only their supported formats and scopes, not exhaustive archives or cutover readiness.

## Ordered uncertainty cases

Run these cases in an authorized isolated collector/backend environment. Do not inject faults against FFVB, LNV, IGN or a shared environment. Use the generated collector client, a local HTTP fault peer and the actual migrated PostgreSQL/F02 owner. Control the response **after** the indicated commit, and count writes independently of received responses. Keep accepted business facts and source locks throughout.

Use the [disposable runtime command](../../README.md#collector-to-sporting-qualification) with `-Dit.test='CollectorUncertaintyIntegrationTest,CollectorSportingBoundaryIntegrationTest'`. The uncertainty peer closes before forwarding or after the backend's committed response; the fencing cases separately hold actual SQL transactions.

1. **Admission response lost:** let the backend commit RUNNING, then drop its response. The collector exposes no provider capability and sends no confirmation GET. Current backend RUNNING excludes further admission until explicit restart. Repeat with failure before commit: a later ordinary poll may allocate a fresh UUID. Backend atomic admission still rejects stale concurrent polls.
2. **Sporting write response lost:** commit one F02 match transaction, then drop the response. Keep that accepted match and independently successful matches. Record unconfirmed integration; never resubmit the mutation or replay the passage. Attempt ordinary completion for the passage. A later ordinary eligible cycle may recover facts still published, subject to newer observation/visibility guards; it cannot reconstruct lost user corrections or custom image bytes.
3. **Completion response lost:** commit completion and drop its response. Report ordinary failure without a confirmation GET or repeated write. The next ordinary poll may admit eligible work because backend completion is authoritative. Repeat with failure before commit: backend RUNNING continues to require inspection/restart.
4. **Validation-result response lost:** commit qualification and completion together, then drop the response. Report failure without same-cycle confirmation or control-completion substitution. Current backend state owns eligibility on later polling; unfinished validation needs inspection/restart and a fresh explicit validation intent.
5. **Replacement during a held transaction:** hold a real F02 transaction after its shared runtime fence and before domain commit. Start registration of a different startup UUID with the current runtime revision. Observe its PostgreSQL lock wait, release and commit the first transaction, then confirm replacement. The committed fact survives; subsequent old-incarnation results, details and terminal writes are refused. Repeat admission versus exact-label closure in both lock orders: closure first prevents admission; admission first permits only that running selected work to finish once.

6. **Mobile operator response lost:** in the operator suites and representative native routes with a controlled backend projection, lose a pause, activation or typed-closure response. Retain the exact target and any closure input for a later explicit action with ordinary feedback. Accept an acknowledgement separately, then fail the following GET and preserve the command outcome. These cases exercise the mobile boundary independently of collector and PostgreSQL evidence.

For every case, retain the original cycle/candidate identity privately, check actual SQL effects and HTTP call counts, and separate confirmed acceptance, refused acceptance and unresolved outcome. Availability evidence does not identify an instant crash: no heartbeat, watchdog, retry worker, sweep, checkpoint or broad reset is involved. An empty/unexecuted selection supplies no failure or recovery observation.

It has no provider client, bootstrap account, import endpoint, archive crawler or automatic follow-up. Use an explicitly authorized isolated destination, its migrated PostgreSQL 18.6 database, one collector and an existing account currently granted `collection.manage`. Export the backend environment as documented in [local development](../../README.md#local-development); Spring does not load dotenv. Keep the operator UUID, connection settings and command output in ignored private runtime files. Override isolation settings only in the process or a private runtime copy. No command below authorizes actual provider access, restoration, reset, logo reassociation, production reconstruction or transition.

After building the backend through the [existing verification target](../../README.md#verification), invoke the same executable for each action:

```sh
java -jar apps/backend/target/backend-0.0.0-SNAPSHOT.jar \
  --spring.profiles.active=initial-reconstruction \
  --blockout.reconstruction.operator="$OPERATOR_UUID" \
  --blockout.reconstruction.action=prepare \
  --blockout.reconstruction.start-year=2023 \
  --blockout.reconstruction.provider=FFVB \
  --blockout.reconstruction.organizer-reference="$OFFICIAL_ORGANIZER" \
  --blockout.reconstruction.candidate-url="$VERIFIED_ARCHIVE_CANDIDATE"
```

Supply each sporting start year explicitly; for example, 2023, 2024, 2025 and 2026 for a 2026/2027 four-season scope. Do not derive a year from today's date or a provider ID. In an open season, preparation can create a missing reference and request asynchronous validation for the unlocked candidate. Reusing the same qualified/locked reference preserves its evidence; a conflicting locked reference or closed season is refused. Wrong-host, unsupported-format and wrong-season evidence remains refused by the existing collector validation. Where compatible structure lacks seasonal attribution, use `action=confirm` with `source-id` and exact canonical `label`; confirmation cannot override invalid evidence.

Read the returned/current source and season state before continuing. A missing archive remains a coverage gap, never a current-feed substitute. Missing classification uses the [existing F02 flow](../002-sporting-data/quickstart.md); this command grants no classification permission.
