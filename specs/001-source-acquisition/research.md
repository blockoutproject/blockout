# Research: acquisition and source operations

## Scope and evidence

Decisions below implement the accepted [F01 scope](spec.md) and reuse the [F13 stack](../003-shared-quality/plan.md), [F02 integration](../002-sporting-data/plan.md) and [F12 authorization](../013-administration-app-configuration/plan.md). Public-source reads were explicitly authorized for this research. Observations dated 2026-10-14 are representative evidence, not exhaustive coverage or production qualification. No raw HTML/CSV, personal contact value or credential is retained here. Withdrawn technical dossiers and independent V1 repositories were not planning inputs.

## Runtime and bounded transport

**Decision**: Use the existing Java/Spring collector boundary, Spring scheduling/executors, Apache HttpClient transport, jsoup 1.23.2 parsing and Commons CSV 1.14.1. Add only Resilience4j RateLimiter 2.4.0 for provider request pacing. The Spring Boot 4.1.1 BOM manages Spring Framework 7.0.9, HttpClient 5.6.4 and HttpCore 5.4.3.

**Rationale**: These ordinary APIs cover the observed HTML/form/CSV inputs, request limits, timeouts and scheduling. [Spring scheduling](https://docs.spring.io/spring-framework/reference/integration/scheduling.html) supplies lenient cron execution and bounded executor configuration. The [HttpClient retry strategy](https://raw.githubusercontent.com/apache/httpcomponents-client/rel/v5.6.4/httpclient5/src/main/java/org/apache/hc/client5/http/impl/DefaultHttpRequestRetryStrategy.java) documents native transient handling and `Retry-After`; use its standard policy with at most two additional attempts: native retryable HTTP statuses are 429/503, and I/O retries require an idempotent method and exclude the strategy’s listed exception classes. A read-only export POST is not automatically idempotent for I/O retry; a retryable HTTP response can still be retried when its request entity is repeatable, as checked by the [native executor](https://raw.githubusercontent.com/apache/httpcomponents-client/rel/v5.6.4/httpclient5/src/main/java/org/apache/hc/client5/http/impl/classic/HttpRequestRetryExec.java). Preserve these limits instead of overriding method classification or adding a retry loop. There is no parser retry or backend mutation retry. [RateLimiter](https://resilience4j.readme.io/docs/ratelimiter) supplies configurable permit periods and bounded acquisition waits without a custom token-bucket implementation.

[jsoup](https://jsoup.org/download) parses HTML without a browser. Its [Connection API](https://jsoup.org/apidocs/org/jsoup/Connection.html) documents a default 2 MB HTTP body limit with truncation: the observed LNV pages exceed it. Fetch bounded, complete decompressed bytes with Apache and pass them to the parser; overflow is a failed observation, not a truncated valid calendar. [Commons CSV](https://commons.apache.org/proper/commons-csv/download_csv.cgi) 1.14.1 is the release selected; the site's 1.14.2-SNAPSHOT banner is not a released-version choice.

**Alternatives rejected**: Spring Batch, Quartz, a broker, generic durable jobs, browser execution and a handwritten retry/pacing loop add lifecycle or infrastructure not required by ordinary ticks and explicit manual recovery. jsoup's convenient HTTP client alone does not meet the chosen transport behavior. Resilience4j's full Spring integration, circuit breakers and retry modules are unnecessary.

**Qualification**: Compile exact managed versions; exercise bounded decoded bytes, redirects, timeout/retry exhaustion, rate limits and executor saturation. Library documentation establishes capability, not the integrated collector's behavior. Limits remain deployment configuration; no throughput benchmark or provider freshness guarantee is inferred.

## FFVB source patterns

**Decision**: Follow official [national](https://www.ffvb.org/119-37-1-Championnats-Nationaux), [regional](https://www.ffvb.org/120-37-1-Championnats-Regionaux) and [departmental](https://www.ffvb.org/122-37-1-Championnats-Departementaux) selectors, frames and organizer menus. Use CSV plus attributable HTML, keeping string identifiers and source context.

**Observed**: Current samples exposed approximately 34 national pools, 18 regional organizers and 70 departmental entries. These are observations, not fixed counts or coverage acceptance. FFVB calendar forms expose `vbspo_calendrier_export.php` with `cal_saison`, `cal_codent`, `cal_codpoule`, `cal_coddiv`, `cal_codtour`, `typ_edition=E`, `type=RES` and `rech_equipe`. Exports were semicolon-delimited Windows-1252 despite an Excel MIME type, with a trailing blank column. HTML default views may be recent subsets; the published `calend=COMPLET` view supplies the full calendar context. Neither a successful response nor a header-only CSV proves a qualified empty scope.

Representative current exports included ABCCS/EFA (132 rows), LIRA/PMA (110), PTCA06/CFA (45) and empty LIRA/CFA and PTIDF75/18M exports. The [EFA source](https://www.ffvbbeach.org/ffvbapp/resu/vbspo_calendrier.php?saison=2026/2027&codent=ABCCS&poule=EFA) also contained recognized bye references. In LIIDF QCM, tour 01 exposed 240 matches across 16 groups; tour 02 exposed 210 across 14. Every row in each shared export used the same `Jo` value. Published group context, not `Jo`, established the partition; reused CMA codes belonged to different rounds. Ordinary matchdays elsewhere remain one pool. Do not generalize a sample match-code prefix into an identity rule.

**Decision**: A shared page/export needed for discovery or an eligible pool may be read once per passage; discard ineligible rows immediately. This permits actual shared-source formats without creating an archive or pending-calendar reserve. Dedicated reads of ineligible pools remain forbidden.

**Historical observations**: Official national archive article references 1247, 1151 and 1076 exposed 2025/2026, 2024/2025 and 2023/2024 respectively; first EFA samples contained 90, 90 and 56 rows. A requested-season schedule also linked current-season material, so validate each linked context. Real 3/F notation was observed; other accepted exceptional-score cases require explicitly synthetic fixtures where not directly observed.

**Club lookup**: The current [official directory form](https://www.ffvbbeach.org/ffvbapp/adressier/recherche.php), linked from [FFVolley](https://ffvolley.org/pratiquer/ou-pratiquer/), submits to `rech_aff_club.php`. Three known club-reference samples returned recognizable club-sheet structures. The former `rech_aff.php` path returned 404; that does not mean the clubs disappeared. `equipe=` is not a global club identity. Only a federation logo was established in these club samples; no FFVB club-logo feed is inferred. No directory-wide crawl is selected.

**Alternatives rejected**: Hard-coded pool inventories, universal code-prefix grouping, CSV string splitting and current-season fallback for absent history lose necessary source meaning. French Cups were inspected for comparison only: their differing grouping does not authorize scope expansion or a progression engine.

## LNV coverage, time and images

**Decision**: Use the official [women's first division](https://www.lnv.fr/competitions/saforelle-volstar), [men's first division](https://www.lnv.fr/competitions/alterna-volstar) and [men's second division](https://www.lnv.fr/competitions/volstar-masculine-2) entries and their published DataProject phase links, without XML or FFVB fallback for sporting facts. The document-only exception in [F03 research](../007-sporting-consultation/research.md) adds qualified information-sheet codes and published PDF references without another sporting authority.

**Observed**: These entries referenced ID/PID/CID 135/193/316, 137/192/315 and 139/196/318 for the current samples. Grouped calendar bodies were approximately 3.48–4.37 MB and contained 156, 182 and 198 unique matches after mobile/desktop deduplication. The DataProject portal root displayed an older season than the official LNV entry pages; it is not an authoritative current-season selector. Historical IDs 113, 115 and 116 exposed separate regular/playoff phase links. Men's playoff phase PID161 contained 22 matches; match 8697 provided set details. Missing standings in that playoff sample does not authorize fabricating a table or claiming every absence is a parser failure.

The sampled current pages did not expose an unambiguous machine-readable season label. Explicit operator confirmation supplies that missing attribution after structure/scope checks. These numeric identifiers are dated evidence, never permanent configuration.

**Time**: [ClientTimeZone.js](https://lnv-web.dataproject.com/js/ClientTimeZone.js) sets a `timezoneoffset` cookie from the browser. For [match 9612](https://lnv-web.dataproject.com/MatchStatistics.aspx?mID=9612&ID=137&CID=315&PID=192&type=LegList), offset 0 displayed 16:00 and −120 displayed 18:00 on 17 October 2026. Pin offset 0 and retain the publication's datetime/visibility flags; otherwise the collector's environment could silently change observed time. The script uses native `Date.getTimezoneOffset()`. Offset-zero rendered times are therefore interpreted as UTC, then normalized with Java time to the existing F02 Europe/Paris local-date/time representation. This interpretation combines inspected script behavior and the observed two-hour difference; calendar/detail fixtures must separately qualify their rendered versus hidden fields, date changes and unknown-time flags. No timezone is inferred for a date-only unknown time.

**Images**: One published [team logo](https://images.dataproject.com/lnv/TeamLogo/100/40/TeamLogo_587.jpg) returned a 1,987-byte JPEG with `Cache-Control: public, max-age=7200`, no ETag or Last-Modified, and refused HEAD with 405. Use GET and native HTTP caching when origin directives permit. This one cache lifetime is not a provider-wide promise. [Apache's caching client](https://hc.apache.org/httpcomponents-client-5.6.x/current/httpclient5-cache/apidocs/org/apache/hc/client5/http/impl/cache/CachingHttpClients.html) supports the bounded in-memory image cache; no persistent cache, custom freshness rule or HEAD-before-GET loop is selected.

Native-cache tests distinguish a changed `200` revalidation body from `304` reuse: Apache's cache status alone labels both as validated. A native response interceptor supplies only the actual response-status evidence for that exchange; cache policy, freshness, eviction and conditional requests remain Apache-owned. Pages/forms use `no-store`; the image cache disables heuristic freshness, asynchronous refresh and stale-on-error substitution.

Additional bounded format observations on 21 October 2026 confirmed the LIIDF shared-round links' `division`/`tour` fields and their explicit `cal_coddiv`, `cal_codtour` and `poule` group fields. The sampled LNV calendar rendered a local clock with `HF_LocalMatchTimeVisible=False` despite offset zero, while its separate detail page rendered the offset-zero clock. That calendar clock remains omitted until independently qualified. A Scoresheet form response exposed its `A_EscorerSheetPdf` anchor after selecting the tab from its actual published order and postback control; no PDF body was requested. These observations do not establish complete provider, historical or operational qualification.

**Cadence decision**: Hourly detail outside the match's own fast window reduces repeated heavy pages while preserving five-minute detail in H−1…H+4. Calendar/standings cadence remains 30/five minutes. First detail at discovery and ongoing ordinary reads after a final result preserve correction opportunities. The owner accepted the lower outside-window detail cadence; this is not a silent optimization.

## Municipal geocoding

**Decision**: Use public IGN Géoplateforme with native municipality/postal filters, no API key or fallback. Unique municipality means success; distinct municipalities mean ambiguity; qualified empty means no candidate. Retain the F02 locality revision with the result.

**Documented**: [IGN guidance](https://ignf.github.io/cartes.gouv.fr-documentation/fr/guides-utilisateur/utiliser-les-services-de-la-geoplateforme/geocodage/), [capabilities](https://data.geopf.fr/geocodage/getCapabilities) and [provider OpenAPI](https://data.geopf.fr/geocodage/openapi.yaml) describe public access, municipality filters and a 50 requests/second/IP limit. Provider OpenAPI 3.1.0 does not change Blockout's 3.0.4 dialect. Retain applicable [terms](https://cartes.gouv.fr/cgu/) and attribution during implementation.

**Observed**: Paris/75015 resolved uniquely to municipality 75056 while returning representative postcode 75001. `ST ETIENNE`/42000 resolved to Saint-Étienne with score 0.609. A strict postcode-equality or arbitrary 0.8 score threshold would reject useful results. Valence/26000 resolved uniquely; Lyon/26000 returned empty; Saint-Denis without sufficient context returned multiple municipalities. An unmatched city filter returned documented-shaped HTTP 400 with `city: No matching cities found`; qualify that specific provider response as no candidate, not a generic service outage. Other errors remain technical unless qualified. Monaco/98000 returned no candidate; the accepted outcome is no point.

**Alternatives rejected**: Mapbox permanent storage would add account/commercial prerequisites; a second geocoder or local fuzzy matching adds inconsistency without an accepted need. A provider score alone never selects between municipalities. The IGN choice and ordinary no-point outcome were accepted by the owner.

## Current state, restart and manual operations

**Mobile preparation drafts**: [Expo protected routes](https://docs.expo.dev/router/advanced/protected/) remove inaccessible screens; the production-route regression reproduces loss of local source input after a pending account refresh fails. Retain one current source editor and one current season/provider workspace per F05 session with RHF's supported [`createFormControl`](https://react-hook-form.com/docs/createFormControl), as at the existing F12 editor boundary. Keep field values RHF-owned, with the original editing revision, explicit-reread requirement and exact launch selection beside each control. Explicit discard and F05 invalidation release them. Local-only component state loses the accepted draft; weakening admission or copying fields into another store would compromise ownership. This adds no persistence, multi-draft registry or recovery queue. Session/resource-scoped generated mutation keys and native [`useIsMutating`](https://tanstack.com/query/v5/docs/framework/react/reference/useIsMutating) prevent a remounted editor competing with its still-pending write. Invalidate held confirmations on unmount and ignore a reread completing after removal, since cancellation can restore an earlier cached success. Synthetic route tests qualify this boundary, not process-death or provider restoration.

**Mobile command uncertainty**: A reproduced A → B → A navigation case discarded a selected control's uncertain acknowledgement when another control replaced its local context. Retain only reconciliation metadata per visited control or season closure for the current F05 session, cleared by explicit successful reread or session invalidation. Discarding typed closure text never discards a sent command's reconciliation requirement. Query still owns request lifecycle and all remote projections; there is no command queue, replay, execution history or persistent draft registry. Replacing this with mutation-history interpretation would couple an operator decision to retained SDK request records without removing the per-control requirement. The [dashboard regressions](../../apps/mobile/src/features/collection/__tests__/collection-dashboard.test.tsx) cover uncertain and successful delayed responses across scope navigation; an acknowledgement cannot replace a same/newer control revision already read, including completion freshness at an unchanged editing revision.

The operational request boundary reads F12's current version observation before and after native credential retrieval. A newly observed unsatisfied minimum prevents a command that has not yet been sent; it does not invent cancellation of an accepted operation. This uses the existing F12 presentation policy, without a separate version cache or a maintenance-bypass header.

**Decision**: One current collector incarnation and current per-control cycle state, with backend admission and a transaction-held runtime fence. Use a startup UUID plus expected runtime revision; a duplicate current startup is harmless and an obsolete registration is refused. Shared locking during writes and exclusive replacement at registration use ordinary [PostgreSQL locking](https://www.postgresql.org/docs/18/explicit-locking.html) and JPA transactions. The fence must precede F02 roots and the account-last grant order.

**Rationale**: A process can remain alive after a replacement starts. Merely checking its token before a transaction leaves a race; holding the row lock through commit prevents old writes after replacement. A global incarnation avoids updating every old cycle. Completed facts remain intact. No lease, distributed lock, heartbeat or persistent work queue is justified. The backend cannot instantly distinguish a crashed collector from a network-isolated one; native availability supervision and later startup supply limited evidence.

Control passages retain only the three behavior-bearing modes: periodic, manual and initial import. Candidate validation is identified by its existing source/candidate context and shares admission protection without becoming a fourth collection mode.

The collector polls pending operator commands every minute. Request acceptance is visible independently of start. Pause cancels pending work, drains a running cycle and resumes only ordinary ticks. Source preparation remains possible for an unlaunched root in an active season. All controls use the one global `collection.manage` grant; sporting grants remain independent. These are owner-approved behavior choices, not implementation assumptions.

**Initial import**: A non-web [Spring ApplicationRunner](https://docs.spring.io/spring-boot/api/java/org/springframework/boot/ApplicationRunner.html) calls existing backend services and authorizes the supplied operator account. Its preparation action reuses canonical season/source services for explicitly supplied historical references, followed by existing validation and classification. It retains the operator-selected scope until ordinary bounded collector admission while historical seasons remain PREPARING. No second writer, bootstrap permission, archive crawler or mobile reconstruction product is needed. Preserve current initial results across targeted retries until the F14 decision; F07 suppression is backend-owned.

**Qualification still required**: Actual Java/generator compilation, source fixtures across all supported structures, PostgreSQL concurrent replacement/write tests, native operator journeys, current permissions, initial-import suppression and operational alert behavior. Public reads and library documentation prove only their inspected boundaries. No provider credentials or configuration were changed, and no production collection or import was run.
