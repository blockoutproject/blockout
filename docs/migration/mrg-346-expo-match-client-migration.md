# MRG-346 Expo Match Client Migration

- Status: implemented in the monorepo shadow baseline
- Owner: Expo mobile application
- Active BFF operations: ten match and live-link reads and mutations
- Production effect: none

## Purpose

MRG-346 migrates every active Expo consumer formerly backed by the handwritten `MatchApi` to the canonical
mobile-gateway v2 operations generated by Orval. Generated wire schemas validate every path, query, command, and
response, while handwritten projections keep transport models out of screens, caches, forms, and navigation state.

The migration does not redesign match discovery, match detail, score, signed-document, live-link, or moderation
workflows. Existing TanStack cache identities, freshness, retry, enablement, infinite-page continuation, feedback,
haptics, ordering, and navigation remain application policy.

## Migrated Operation Set

| Operation ID | Mobile workflow               | Consumer boundary                |
| ------------ | ----------------------------- | -------------------------------- |
| `BFF-P-07`   | read match detail             | public match detail              |
| `BFF-P-08`   | list grouped match days       | public match discovery           |
| `BFF-S-13`   | create or update live link    | deferred editable live-link form |
| `BFF-S-14`   | deactivate active live link   | live-link form and moderation    |
| `BFF-S-15`   | report active live link       | deferred editable report form    |
| `BFF-S-16`   | list live-link history        | match moderation history         |
| `BFF-S-17`   | list matches for moderation   | live moderation queue            |
| `BFF-S-18`   | approve pending live link     | match moderation history         |
| `BFF-S-19`   | reject pending live link      | match moderation history         |
| `BFF-S-20`   | reactivate eligible live link | match moderation history         |

`BFF-P-06` remains an indirect browser request through signed URLs supplied by `BFF-P-07`; Expo has no separate API
caller to migrate. The handwritten match client and its `MobileGatewayApi` authentication propagation disappear.
Generated secure calls continue to receive the existing Auth0 token supplier and single unauthorized-session callback
through the shared Orval mutator.

The coexistence matrix's `COMP-02` association read remains upstream BFF enrichment represented inside the generated
match projections. `COMP-03` has no active BFF or Expo caller. MRG-346 therefore activates no direct owner-service
competition client and invents no unused mobile endpoint.

## Query, Pagination, And Projection Ownership

- Match detail retains the `enrichedMatches` cache key, zero freshness, disabled/missing identifier behavior, and
  no-retry policy.
- Match discovery retains its status, sorted pool identifier, sorted team identifier, and page-size cache identity;
  five-minute freshness; infinite-query continuation; and no-retry behavior.
- Match-day, pool-group, match, and ranking array order remains server-authoritative. No client sort or missing-row
  synthesis is introduced.
- Nullable match-list sides remain explicit. The existing row renders an empty identity and neutral image fallback
  when either BFF side is unavailable instead of failing the complete day page.
- Detail remains all-or-error and projects canonical team, pool, ranking, division, live-link, and signed-document
  fields into named handwritten views.
- Query cancellation signals now reach every generated read transport.

The canonical history and moderation operations are paginated, while the existing Expo screens consume complete
arrays. Their adapters therefore request sequential pages at the documented maximum of 100, preserve page and item
order, stop only when `hasNext` is false, and forward cancellation. Existing screen-owned filtering and display sorts
remain unchanged.

## Mutation And Form Boundaries

Live-link create/update, deactivate, report, approve, reject, and reactivate commands validate route parameters and
request bodies before calling generated transports, then validate their narrow or empty responses. Existing error
normalization, explicit refetches, feedback, haptics, moderator checks, and mutation ordering remain unchanged.

`MatchLiveLinkForm` and `MatchLiveLinkReportForm` retain their current Formik/Yup fields, touched state, validation
text, external submit registration, loading, feedback, and haptics. MRG-512 and MRG-513 remain the only owners of their
React Hook Form/Zod migrations.

## Compatibility And Rollback

The remaining handwritten User, Search, Notification, and Report clients stay available for MRG-347. Shared v1 case
conversion and released-server v1 routes remain available until their approved retirement gates. Before a production
Expo v2 release, rollback may use the preceding Expo build and standalone v1 server images. After such a release, the
last-known-good dual-route mobile-gateway and owner-service images remain the server rollback baseline. This task
authorizes no store release, OTA update, EAS build, deployment, or traffic switch.

## Verification Evidence

- Mobile typecheck proves all ten generated operations, wire schemas, projections, cache types, and pagination
  adapters compose without exposing generated models to the screen layer.
- The existing form-boundary guard still reports exactly eight transition-only Formik/Yup forms; MRG-346 migrates
  form transport only.
- Existing form contract tests, the complete REST contract suite, and OpenAPI source lint remain green.
- Two direct Orval generations leave generated output clean, and a fresh Expo export builds both Android and iOS
  Hermes bundles.
- Documentation, Nx project inspection, Maaatch comparison, source confinement, targeted formatting, and whitespace
  checks remain publication gates.

## Closed Scope

- No OpenAPI source, generated artifact, Orval configuration, dependency, environment value, route, native plugin,
  backend, database, event, scraper, standalone repository, production, or Maaatch change.
- User, search, notification, and report callers remain assigned to MRG-347.

- The active goal stops before Phase MRG-900.
