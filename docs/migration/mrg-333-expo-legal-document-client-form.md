# MRG-333 Expo Legal Document Client And Form Migration

- Status: implemented in the monorepo shadow baseline
- Owner: Expo mobile application
- BFF operations: `BFF-P-05` and `BFF-S-07`
- Production effect: none

## Purpose

MRG-333 completes the first vertical contract-first consumer pilot. The legal-document screen now reads from the
canonical mobile-gateway v2 operation generated by Orval, and the editor submits through the generated v2 mutation.
The migrated slice performs no snake_case/camelCase conversion and no longer depends on the handwritten legal methods
that previously lived in `ConfigApi`.

The same task migrates `LegalDocumentForm` from Formik/Yup to React Hook Form/Zod. This is the first implemented example
of the three-shape form policy: generated wire schema, handwritten form schema, and generated request type remain
separate.

## Boundary Ownership

| Boundary                  | Owner                                          | Responsibility                                                                    |
| ------------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------- |
| generated read/mutation   | Orval `MobileLegalDocuments` output            | v2 paths, Axios transport, query key, request type, and response type             |
| generated wire validation | Orval Zod `MobileLegalDocuments` output        | runtime validation of canonical read and update payloads                          |
| domain query hook         | `hooks/config/legalDocument`                   | one-hour stale time, generated query key, wire validation, and view projection    |
| screen view model         | mobile-owned `LegalDocument`                   | legal discriminator and controlled string values; no persistence/audit fields     |
| form contract             | `components/user/legalDocumentFormContract.ts` | defaults, exact French messages, input constraints, and typed request transform   |
| form orchestration        | `LegalDocumentForm.tsx`                        | controllers, touched feedback, external submit, loading, haptics, toast, mutation |
| sheet/footer              | existing `LegalDocumentFormSheet`              | registration callback, disabled/loading state, close-after-success behavior       |

Generated DTOs do not become form state. The read hook validates the generated wire response and immediately projects
nullable API fields to controlled native input strings. The handwritten form schema owns the existing non-empty rules
and messages. A named transform returns `UpdateMobileLegalDocumentRequest`, and the generated update schema validates
that request before the generated mutation executes.

## Preserved Behavior

- The read query retains its one-hour stale time and screen-owned refetch/error/loading behavior.
- The form still edits title, version, and Markdown content with the same placeholders and exact required messages.
- Required validation still does not trim whitespace.
- Errors remain visible only after the relevant native field is touched.
- `canSubmit` remains validity plus not-loading, and the external footer still invokes the registered submit function.
- Resource changes reset defaults, validation, dirty state, and touched state to the new document.
- Medium submit, success, error, footer, toast, and close-after-success haptic/interaction paths remain unchanged.
- The global QueryClient, retry behavior, cache defaults, Axios timeout, authentication, and `401` handling are
  unchanged.

Formik and Yup remain installed for the eight allowlisted forms that have not migrated. The form-boundary guard now
rejects any reintroduction of either package into `LegalDocumentForm`.

## Removal And Rollback

Only the two legal-document methods were removed from handwritten `ConfigApi`; all other v1 mobile calls remain on
their current clients. The mobile-gateway and config-service v1 routes and adapters remain available under the MRG-304
coexistence policy.

Before a production Expo v2 release, rollback may use the previous Expo build and the standalone v1 server images.
After a v2-compatible Expo release is active, the last known-good dual-route mobile-gateway and config-service images
must remain the server rollback baseline. This task does not authorize a store release, v1 removal, deployment, or
production traffic switch.

## Verification Evidence

- Seven hermetic contract tests prove defaults, the typed request transform, exact messages, no new trim behavior,
  nullable wire projection, and legal discriminator validation.
- The Nx form guard reports eight transition-only Formik/Yup forms and rejects legacy imports in the migrated form.
- Mobile typecheck proves generated operation, schema, request, React Hook Form, and screen view-model integration.
- Android and iOS exports, deterministic Orval generation, documentation validation, and whitespace checks remain the
  publication gates.

## Closed Scope

- No BFF, backend service, database, RabbitMQ, scraper, standalone repository, Maaatch, or production change.
- No global cache, retry, authentication, timeout, navigation, layout, or copy change.
- No Formik/Yup removal outside the legal form; MRG-507 through MRG-516 own the remaining migrations and retirement.
- MRG-377 remains the next roadmap task and owns OpenAPI source-syntax normalization.
- The active goal still stops before Phase MRG-900.
