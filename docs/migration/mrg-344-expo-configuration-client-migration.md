# MRG-344 Expo Configuration Client Migration

- Status: implemented in the monorepo shadow baseline
- Owner: Expo mobile application
- Active BFF operations: ten configuration reads and mutations
- Production effect: none

## Purpose

MRG-344 migrates every active Expo consumer formerly backed by handwritten `ConfigApi` methods to the canonical
mobile-gateway v2 operations generated by Orval. The existing Axios mutator remains the single generated transport and
continues receiving the Auth0 token supplier and unauthorized-session callback through the application session
boundary.

The task does not change the app-status, division, raw-division-mapping, or scraper administration flows. Handwritten
TanStack queries retain their existing freshness, enablement, manual refresh, feedback, haptic, and screen projection
policy while generated wire schemas validate canonical responses and mutation inputs.

## Migrated Operation Set

| Operation ID | Mobile workflow             | Consumer boundary                        |
| ------------ | --------------------------- | ---------------------------------------- |
| `BFF-P-02`   | read application status     | session gate and administration query    |
| `BFF-P-03`   | list divisions              | division lists, selectors, and search    |
| `BFF-S-02`   | update application status   | administration maintenance/version cards |
| `BFF-S-03`   | create division             | deferred Division form transport         |
| `BFF-S-04`   | update division             | deferred Division form transport         |
| `BFF-S-05`   | deactivate division         | division administration item             |
| `BFF-S-08`   | list raw-division mappings  | mapping administration query             |
| `BFF-S-10`   | update raw-division mapping | deferred mapping form transport          |
| `BFF-S-11`   | update scraper switch       | administration scraper control           |
| `BFF-S-12`   | list scraper switches       | administration scraper query             |

The generated get-division, create-raw-mapping, and get-raw-mapping operations remain available without a new Expo
caller. Source inspection still finds no product consumer for them, so MRG-344 does not invent one. The two unused
handwritten raw-mapping methods disappear with `ConfigApi` instead of being recreated around generated operations.

## Query And View Ownership

- App status keeps `staleTime: 0`; divisions, raw mappings, and scraper switches keep one-minute freshness.
- Optional league and season filters remain query-key inputs and use the generated canonical `leagueCode` parameter.
- Queries forward TanStack cancellation signals to generated operations.
- Generated list wrappers are validated and immediately projected to the existing array views.
- Division, raw-mapping, scraper, and app-status transport types do not become screen or form state. Named mappers
  retain the mobile enum identities and only the fields current screens consume.
- Manual refetch after administration mutations remains screen-owned. No global QueryClient, retry, invalidation,
  navigation, loading, empty-state, or feedback behavior changes.

## Authentication And Multipart Boundaries

`SessionProvider` continues to configure both remaining handwritten clients and the Orval Axios mutator through the
existing `setAuthOnApis` entry point. Removing the configuration member from `MobileGatewayApi` therefore removes only
obsolete v1 transport propagation; generated secure calls still receive the same token supplier and the same single
`401` cleanup callback. Public generated calls use the same mutator without introducing a second client or provider.

Division image selection and manipulation remain owned by the existing Formik form. A named React Native multipart
adapter preserves the established URI, filename, and MIME-type FormData part behind Orval's browser-oriented `Blob`
signature. Generated multipart assembly emits canonical camelCase JSON and no longer uses the legacy deep
snake-case helper for this workflow.

## Forms, Compatibility, And Rollback

`DivisionForm` and `RawDivisionMappingForm` retain their current Formik/Yup or manual-state behavior, exact fields,
validation, selectors, images, colors, touched state, external submit registration, loading, haptics, and visible
messages. MRG-510 and MRG-511 remain the only owners of their later React Hook Form/Zod migrations.

The remaining handwritten resource APIs, shared v1 case conversion, and released-server v1 routes remain available.
MRG-345 through MRG-347 own the other Expo workflow cutovers, and MRG-353 owns final Expo case-conversion retirement.
Before a production Expo v2 release, rollback may use the preceding Expo build and standalone v1 server images. After
such a release, the last-known-good dual-route mobile-gateway and config-service images remain the server rollback
baseline. This task authorizes no store release, OTA update, EAS build, deployment, or traffic switch.
