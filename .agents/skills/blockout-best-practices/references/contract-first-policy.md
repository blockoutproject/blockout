# Blockout Contract-First Policy

Read this before adding or changing OpenAPI sources, generated transport types, transport enums, server interfaces, or
service-to-service clients.

## Ownership And Layout

Keep authoritative OpenAPI fragments under `libs/shared/contracts/specs/source`:

```text
source
├── shared
│   ├── base.json
│   └── schemas
│       └── *Enum.json
└── services
    └── <service>
        ├── base.json
        ├── paths
        └── schemas
```

- A service owns its operations and DTO schemas. A DTO does not move to `shared` merely because several consumers use
  it; consumers generate from the owner's contract.
- `shared/schemas` contains reusable transport enums. Use a stable `*Enum` component name and reference it from service
  schemas.
- Application policies such as `DataSourcePriority` remain handwritten in their owning application. Provider-owned
  values remain in provider adapters.
- Keep the existing V1 paths and native camelCase fields. Never introduce V2 names, compatibility DTOs, Jackson naming
  aliases, or case-conversion layers during generated adoption.

## Generated Output

- Java shared enums are generated by Maven into `apps/backend/shared-models/target`. Server interfaces and internal
  clients are generated under the owning Maven consumer's `target/generated-sources/openapi` directory.
- Python models and asynchronous HTTPX clients are generated with the pinned OpenAPI Generator CLI into the private
  `libs/shared/python-contract-clients` wheel. Use one declarative batch configuration per contract.
- TypeScript is generated only from the mobile-gateway contract with Orval into
  `apps/frontend/mobile/src/shared/generated`. Mobile never consumes an internal service contract directly.
- Never edit generated code, add custom generator templates, or commit generated sources. Prefer native generator
  configuration; add a script only when the official tools do not provide the required operation.

## Readiness Gate

Before adding a service contract, its dedicated roadmap task must use focused tests to prove that every active
handwritten mirror has:

- the final role name, such as `CreateClubInternalRequest` or `ClubInternalResponse`;
- the owner's exact camelCase fields, types, nullability, nesting, and enum values;
- no legacy DTO, V2, alias, or duplicate complete-resource residue;
- characterization evidence for every active producer and consumer.

Generated adoption then replaces imports and deletes the proven handwritten mirrors. It must not conceal another model,
business, route, or serialization redesign.

## Tooling

- OpenAPI Generator 7.22.0 is the common Java and Python engine.
- The Python workspace installs the official PyPI CLI. The shared contract generates models only; service contracts
  use the official `httpx` library option and CLI batch command.
- Java uses `openapi-generator-maven-plugin`; shared schema mappings are synchronized from the shared enum fragments.
- Orval is reserved for the future mobile-gateway TypeScript client. Its configuration belongs to that vertical and is
  not created before the mobile-gateway contract exists.
- Nx is a thin orchestrator over these native tools.

Use `@blockout/contracts:generate-contracts` and `@blockout/contracts:test` for contract sources. Generation, build, and
test targets for a generated client or model belong to the project that owns that output; use the generator's native
clean mode instead of a cleanup wrapper. Completion requires two clean identical generations, clean Java and Python
package builds/imports, and proof that Git tracks no generated artifact.
